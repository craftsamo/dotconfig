# Media craft evaluation contract

These are test instructions outside skill discovery, not production authority or
a claim that any media has been generated or judged. The JSON cases beside this
file describe expected behavior; a passing schema test does not execute them.

## Fixed scope

Current hands subjects: image icon/emoji/mascot/reimagine/kit/card; video
clip/tour/ad/explainer-video/music-video; audio speech/sfx/music/mix. Exercise
supported operations only. Preserve existing legacy routes and test that craft
does not turn an unavailable hands operation into a silent fallback.

Here, hands means the host's media-producing profiles. Case `operation` labels
describe the pedagogical action, not an executable producer verb. The later host
integration tests own the mapping to actually supported verb/subject pairs.

For each subject, choose an original, non-private representative task with an
observable audience goal and protected conditions. Use one actual-media comparison
per subject for the first acceptance round, plus a composite with visual, voice,
bed and cue relationships. Request only targeted re-comparisons after findings.
No real client session, private character identity or unlicensed reference asset
belongs in the public fixtures. Existing private artifacts stay local evidence.

## Separate the evidence tiers

1. Structural: frontmatter, unique names, direct conditional links, case fields,
   profile wiring and ownership. This proves discoverability, not instruction use.
2. Fresh-context behavior: supply the request and authorized inputs, not the
   expected answer. Retain actual resource reads, decisions, handoffs and outcomes.
   Cover positive, near-miss, retain/no-op, revise and unavailable-control cases.
3. Production: run the actual permitted producer, preserve raw outputs and failed
   attempts, and inspect the resulting artifacts. Synthetic fixtures prove runtime
   behavior only, not image-model fidelity, voice performance or musical quality.
4. Acceptance: compare against the task's fixed goal and protected conditions.
   Visual checks locate evidence in actual frames/crops. Temporal checks state
   whether normal-speed playback occurred. Audio craft requires human listening
   this round; meters and ASR remain separate evidence.

## Baseline and candidate

Freeze the task, reference set, model/engine identity, available controls, output
constraints and attempt budget before comparison. Give baseline and candidate the
same brief and equivalent allowances; keep all attempts rather than selecting a
strong candidate against a weak baseline. Record differences in engine availability
or nondeterministic generation. One pair is a case result, not statistical proof
of universal quality improvement.

Use neutral A/B labels where practical and withhold the production explanation
until the observer gives a first-reading/listening judgment. Disclose image scale,
video sampling, audio level differences and any approved review-copy processing.
Never change an original or final master merely to make a comparison fair.

Assess intent fidelity, perceptual hierarchy, execution of the chosen mechanism
and coherence with the whole. Not every axis applies equally to every subject;
do not impose a shared look, motion recipe, loudness target or numerical taste
score. Record wins, ties, regressions and unverified claims. Explicit unmet
conditions cannot be averaged away by appeal elsewhere.

## Release boundaries

Source authoring, tests and isolated local checks do not authorize model charges,
reference uploads, new engines, publication or live configuration changes. Before
metered comparisons, obtain a current-work estimate and call/amount ceiling. A
failed attempt remains consumed where the producer counts it. The proposal stage
stays zero-production even when a later study would be cheap or local.

All-family quality acceptance stays incomplete while any required paid render,
visual comparison or human audio review is missing. Report each tier separately;
do not replace actual-media tests with prompt simulations to claim completion.
Live rollout and fresh-session smoke tests require a separate explicit release.
