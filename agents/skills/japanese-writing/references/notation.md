# 表記と文体の既定値

日本の技術・実務文書で違和感なく読める標準的な表記ルールです。Microsoft ローカライズ規約のような翻訳調のスペース強制（`10 月 8 日`、`1 つ`、`ダイアログ ボックス` など）は採らず、日本語として自然な読みやすさと文書内の一貫性を重視します。

## 優先順位

1. 依頼の指示、対象リポジトリ・媒体・顧客のスタイル規約を最優先します。
2. 既存の文書を編集・追記するときは、その文書やリポジトリで一貫している表記・文体に合わせます（例: 和欧間スペースなしで統一された文書ならそのまま維持する）。
3. 指定も既存慣習もない新規文書で、以下の既定値を使います。

引用、固有名詞、商標、コード識別子、コマンド、ファイルパス、URL は原文の表記をそのまま保持します。

## N1 和欧間のスペース

- 英字・インラインコードと日本語の間には、原則として半角スペースを1つ入れます（例: `Git の履歴`、`API を呼び出す`、`` `git status` を実行します ``）。ただし、既存文書がスペースなし（`Gitの履歴`）で統一されている場合は無理にスペースを入れません。
- **数字と日本語（年月日・助数詞・序数）の間にはスペースを入れません**: `2026年10月8日`、`第4版`、`7柱`、`1枚`、`1つ`、`3か月`、`1分以上` と詰めて書きます（`10 月 8 日` や `1 つ` のように離さない）。
- 句読点（「、」「。」）や括弧と英数字の間にはスペースを入れません（例: `設定を保存して、Windows を再起動します`）。
- ひらがな・漢字どうしの間には空白を入れず、行頭以外の全角スペース（U+3000）は使いません。

## N2 数字・単位・範囲

- 算用数字は半角で書きます（全角の `０〜９` は使わない）。
- 数字と英字単位の間には半角スペースを入れます: `100 MB`、`250 ms`、`3 kg`（既存文書が `100MB` で統一されていれば維持してよい）。
- `%`、`°`、`℃` は数字に詰めて書きます: `50%`、`45°`、`20℃`。
- 3桁区切りは半角カンマ、小数点は半角ピリオドを使います: `7,770`、`1.5倍`。
- 範囲の表記: 波ダッシュ `〜`（`1〜2文`、`0〜99`、`9月1日〜30日`）と「から」（`0から99まで`）のどちらも使えます。1つの文書内で揃え、半角チルダ `~` は範囲記号に使わないようにします。

## N3 句読点と疑問符・コロン

- 句読点は全角の「、」「。」を使います（全角カンマ・ピリオドが規約で指定されている学術・技術文書を除く）。
- 疑問符・感嘆符・コロンは、全角（`？`、`！`、`：`）と半角（`?`、`!`、`:`）のどちらを使う場合も文書内で統一します。半角の `?` や `!` の後ろに文が続くときは半角スペースを1つ入れます（例: `保存しますか? 保存しない場合は...`）。語末の記号の前に空白は入れません。
- 説明文では感嘆符（`!`・`！`）を乱用せず、「。」で落ち着いて終えます。

## N4 括弧と引用符

- 補足説明の括弧は、全角括弧 `（補足）` と半角括弧 ` (補足) `（日本語と接する外側に半角スペース）のどちらも使えます。**1つの文書内で必ずどちらかに統一**し、混ぜないでください（迷ったら日本語の地の文に馴染む全角 `（）` を使います）。
- 半角括弧を使う場合でも、アクセスキー `保存(S)` や商標 `Microsoft(R)` の前は詰めます。括弧や引用符の内側に余分な空白は入れません。
- 会話・引用・強調する語句にはかぎ括弧（「引用」）、書籍や媒体名には二重かぎ括弧（『媒体名』）を使います。日本語の語句を直線の半角引用符 `"..."` で囲みません。

## N5 記号

- スラッシュは半角で前後を詰めます: `オン/オフ`、`3/14`。
- 三点リーダー `…`（または `……`）や半角の `...` は文書内で揃えて使います。
- チェックリスト末尾の Issue・PR 参照（例: `- [x] モジュールを追加 — #63`）のように、構造上の区切りとして前後にスペースを置いたダッシュ ` — ` は自然に使って構いません。日本語の文中に詰めてダッシュを差し込む欧文風の挿入（`結論—まず試す`）は避け、読点や括弧で書きます。
- 全角の英記号（`％`、`＃`、`＆`、`／`、`＋` など）は使いません。地の文では `&` より「と」「および」を優先します。

## N6 カタカナ語と中黒

- **複合カタカナ語はスペースを入れず続けて書きます**: `ダイアログボックス`、`タスクバー`、`コントロールパネル`、`インラインコード`、`コードブロック`（英語の語間に合わせて `ダイアログ ボックス` のように区切らない）。
- 長音: 一般的な表記（`サーバー`、`ユーザー`、`ブラウザー`、`フォルダー`、`パラメーター`、一方で `メモリ`、`カテゴリ`、`ディレクトリ`、`セキュリティ`、`プロパティ`、`プロセッサ`、`コンパイラ` など）を目安としつつ、対象リポジトリや技術分野の慣用（`サーバ`・`ユーザ` 統一など）があればそちらに揃えます。
- 中黒（`・`）: 外国の人名・地名の区切りのほか、同格の名詞をコンパクトに並列するとき（「設計・実装・テスト」「調査・分析レポート」「追加・変更されたファイル」）にも自然に使えます。
- 半角カタカナは使いません。

## N7 漢字とかなの使い分け

常用漢字表と送り仮名の本則を基本とし、以下の形式名詞・補助動詞・接続詞は原則としてひらがなで書きます。

| かなで書く語 | 漢字で書かない形 | 備考 |
|---|---|---|
| ください、いただく | 下さい、頂く | 補助動詞（「〜してください」） |
| できる | 出来る | 「出来事」「出来高」は漢字 |
| とき、こと、ため、ように、とおり | 時、事、為、様に、通り | 形式名詞として使う場合 |
| および、または、ならびに、ただし、さらに、すでに、あらかじめ、ほとんど | 及び、又は、並びに、但し、更に、既に、予め、殆ど | 接続詞・副詞（法令・規程文を除く） |
| 〜してみる、〜していく | 〜して見る、〜して行く | 補助動詞 |

形式名詞のかな書きを、**自然な漢語熟語の分解や日常的な常用漢字の過剰なひらがな開きと混同しないでください**。「起動時」「確定後」「変更内容」「調査結果」「未決事項」「自動化」「具体的」はそのまま漢字で書きます（「起動のとき」「調べたこと」のように崩さない）。また、「半年経ちました」「他のメンバー」「机の上」「顔ぶれ」のように大人の文章で普通に使う漢字も、不必要に「半年たちました」「ほかの人」と開かないでください。

## N8 数字と漢数字

- 数量・順序・日付など他の数に置き換えられる数値は算用数字（`3個`、`第2章`、`10月8日`）で書きます。
- 慣用句や語の一部は漢数字で書きます: `一時的`、`もう一度`、`四捨五入`、`一般`、`統一`、`一文`、`一部`。なお「1つ・一つ」「2つ・二つ」は文脈に応じてどちらも自然に使えます。
- 助数詞の「か月」「か所」「個」にカタカナの「ヶ」「コ」は使いません（`3か月`、`2か所`、`5個`）。

## N9 文体と敬語

- 基本の文体: 記事、ガイド、連絡文だけでなく、**GitHub の Issue・PR 本文や設計・調査の共有文書も落ち着いた「です・ます」調（敬体）を既定**とします。「だ・である」調（常体）を既定にするのは論文、公的文書、規程・約款、常体で書くエッセイ、または対象リポジトリが常体で統一されている場合です。
- 敬体の純度と語彙のバランス: 「です・ます」調の地の文の途中で、文末の変化を狙って常体の現在形（「〜と後回しにしてしまう。」など）を1文だけ混ぜたり、大げさな強調の「〜たのです。」を挟んだりしないでください（references/expression.md X7）。また、「です・ます」調で書くときほど語彙まで日常の幼児語（「足します」「当てます」「絵」「置き場」など）に落とさず、正確で簡潔な実務・技術語彙（「追加します」「適用します」「画像」「永続化ストア」「推奨します」など）を選びます。
- 見出し・表・箇条書き: 見出しや表のセルは体言止めまたは簡潔な言い切りにします（見出しを「〜します」で終えない）。同じ階層の箇条書きやチェックリスト（`- [ ]`）は、セクション内で文末の形を揃えます。
- 敬語の節度: 社外・顧客向け文書以外では過剰な尊敬語・謙譲語を使わず、回りくどい二重敬語や過剰表現は避けます。
- 重複表現（「各〜」と「〜ごと」の重ね使い）は一方に絞り、意味が曖昧になりやすい語は明確な語（「適切な」など）を選びます。

## N10 包摂的な表現

- 性別を限定する職業名は中立な語を使います（`看護師`、`客室乗務員`、`保育士`、`営業担当者`）。
- 読み手の能力を決めつける「初心者でも簡単」のような表現は避け、「初めて設定する場合」のように状況で書きます。
- 技術用語でも置き換えが定着している場面では `プライマリ/セカンダリ`、`許可リスト/拒否リスト` を優先します（既存の API 名・設定キー・プロトコル仕様を指す場合は原文どおりに書く）。

## N11 Markdown の書式

- CommonMark では `**` の内側が約物で外側に文字が続くと太字として描画されないことがあります。「**重要**」のように括弧を外に出すか、外側に半角スペースを入れます（inspector の `bold_not_rendered` が検出します）。
- 独立した並列項目には箇条書き（`-`）、順序に意味のある手順には番号付きリスト（`1.`）、複数軸の比較には表を使います。
