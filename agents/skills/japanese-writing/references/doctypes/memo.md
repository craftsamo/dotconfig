# リサーチメモ・ディスカッションペーパー・企画書・提案書

※ GitHub の Issue・PR や技術仕様書はこの文書型ではなく、対象リポジトリのテンプレートと references/genres.md の `tech` に従います。

## この文書が答える問い

まだ確定していない施策や方針について、「何を提案し、誰にいつまでに何を判断してほしいか」「どこまで事実が確認できており、何が未解決の論点か」を明確にして意思決定を引き出す文書です。

| 文書種別 | 結論の確度 | 読み手に求めること |
| --- | --- | --- |
| リサーチメモ | 暫定 | 見立ての妥当性確認、追加情報の提供 |
| ディスカッションペーパー | 暫定 | 論点に対する賛否・意見 |
| 企画書・提案書 | 提案側としては確定 | 実施承認、予算・体制・スケジュールの決定 |

## 必須要素と構成

1. **中心主張と求める判断（冒頭）**: 「〜の検討について」のような曖昧な表題を避け、タイトルと冒頭数文で「何を提案し、誰にいつまでに何を決めてほしいか」を示します。暫定結論であっても「現時点の見立て」と明記したうえで冒頭に置きます。
2. 対象範囲と対象外: 今回扱わない論点には、漏れと誤解されないよう対象外とした理由（「料金改定は別プロジェクトで協議中のため対象外」など）を一言添えます。
3. 選択肢の比較: 各案のメリット・デメリットを別々に箇条書きで並べるより、共通の評価軸（初期費用、導入期間、期待効果、撤退の容易さ、運用負荷など）で表にまとめます。根拠がないのに並列の選択肢へ「フェーズ1」「最優先」といった順位を付けません。
4. 未解決の論点と暫定の見立て: 「今後の検討課題」と列挙するだけでなく、論点ごとに現時点の見立てと、判断に足りない情報（誰に何を確認すれば決まるか）を書きます。
5. 根拠・リスク・体制（提案書）: 主張を支える実数・事例（出典付き）、想定リスク、体制とスケジュールを示します。

## 短い例

Before（論点の羅列のみで判断材料がない）:

> # シェアサイクル導入の検討について
> 近年、各地でシェアサイクルが広がっている。本メモでは当市における導入の可能性を検討する。論点は駐輪拠点の配置、運営事業者の選定、安全確保であり、今後さらに検討を進める必要がある。

After（主張・求める判断・比較軸・未解決点を明示）:

> # 駅周辺12拠点で6か月間のシェアサイクル試験導入を行い、貸出密度で本導入を判断する
>
> 来年4月から6か月間、市内主要2駅の半径 1.5 km 圏内に12拠点を設ける試験導入を提案します。交通政策会議には、試験予算（概算840万円）の承認と、評価指標を「1拠点あたり1日平均貸出回数」とすることの決定を11月中にいただきたいと考えています。なお、利用料金の細目は財政課と別途協議中のため本メモの対象外とします。
>
> 運営方式は「市直営」と「民間委託」の2案を、初期費用・開始までの期間・撤退の容易さの3軸で比較しました（別紙表）。試験段階では撤退しやすい民間委託案が妥当と見ています。未解決の論点は夜間の放置車両回収体制であり、事業者ヒアリング後に見積もりを確定します。
