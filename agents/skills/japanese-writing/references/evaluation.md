# 診断と仕上げの評価

点数を使う場面は 2 つあります。
依頼された文章を書き換えずに診断する「診断」と、書いた文章を渡す前に確かめる「仕上げの評価」です。
どちらの点数も、文章の型と読み手の負担を測る目安です。
誰が書いたか (人か AI か) の判定には使いません。「AI が書いた」とも「人が書いた」とも報告しません。

## 診断

「この文章を採点して」「どれくらい不自然か見て」のように、書き換えを伴わない依頼で使います。
診断の間は原文を変更しません。直すかどうかは、結果を見た依頼者が決めます。

### 機械スコア

inspector の naturalness モードが score を返します。

```text
減点 = (critical × 8 + warn × 4 + info × 0.5) × 1000 / max(文字数, 1000)
機械スコア = max(100 − 減点, 20)
```

- 数えるのは naturalness モードの通常の規則だけです。experimental の規則、reading-load、expression、notation の指摘は点数に入りません。
- 文字数は Markdown の記号や改行を含む全体の長さです。
  1000 文字未満の文章も 1000 文字として割るため、短い文章では減点が小さく出ます。短い文章は帯より規則ごとの件数を見ます。
- 同じ箇所を 2 つの規則が別の観点から指摘することがあり (翻訳調の正規表現と形態素の両方など)、点数にはどちらも入ります。
- 100 文字未満の文章は採点しません (score.reason が too_short)。
- Sudachi が使えず naturalness の一部が未検査のときは、score.value が null になります (score.reason が naturalness_unverified)。
  その場合は点数を出さず、未検査であることと、手で確かめた範囲の所見だけを報告します。

### 深さ

| 深さ | 手順 | 点数 |
|---|---|---|
| quick (既定) | naturalness と reading-load を実行し、指摘の多い型を確かめる | 機械スコアをそのまま使う |
| full | 全文を読み、指摘を文脈で確かめ、道具が拾えない型 (X9 具体性不足、J1 結論の位置など) も見る | 機械スコアを ±15 の範囲で調整する。調整には必ず理由を付ける |

調整の例です。

- 指摘された表現の多くが文脈上必要 (引用、用語の定義、意図的な反復) なら加点します。
- 指摘がなくても、全体が一般論だけで具体的な事実がない、結論が最後まで出ないなどの問題があれば減点します。

最終の点数は 0 から 100 に収めます。
quick の機械スコアが、全文を読んだ印象と大きくずれるとき (定型だらけなのに minor など) は、full に切り替えて調整します。

### 帯

| 点数 | 帯 (score.band) | 意味 |
|---|---|---|
| 90 から 100 | natural | 型の偏りはほとんどない |
| 70 から 89 | minor | 部分的に直すと読みやすくなる |
| 50 から 69 | needs_revision | 型の偏りが読み手の負担になっている |
| 0 から 49 | strong | 文書全体で型が目立ち、構成から見直す必要がある |

### 診断の報告

1. **総合**: 点数、帯、深さ。full で調整したなら、機械スコアと調整の理由。
2. **根拠**: 規則ごとの件数と、多い型の要約。expression.md や readability.md の該当項目を示します。
3. **気になる箇所**: 5 か所まで。行番号と短い抜粋、何が読み手の負担かを書きます。
4. **直すなら**: 方向だけを示します。書き直した本文は、依頼されるまで出しません。

## 仕上げの評価

書いた文章、または直した文章を渡す前に使います。
full モードでは必須です。quick モードでは、6 つの観点を頭の中で確かめるだけで構いません。

### 6 つの観点

| 観点 | 問い | 見る資料 |
|---|---|---|
| 1. 自然さ | 決まり文句、翻訳調、均質なリズムが読みを妨げていないか | expression.md |
| 2. 密度と簡潔さ | 一文ごとに情報があるか。前置き、繰り返し、水増しがないか | constitution.md 第 1 条、readability.md D1、H1 |
| 3. 機能と見通し | 読み手が目的の情報にすぐ届くか。見出し、段落、箇条書きが内容に合っているか | doctypes/*.md、constitution.md 第 2 条、第 3 条 |
| 4. 論理の明確さ | 主張、理由、根拠のつながりが追えるか。接続詞が実際の関係と合っているか | readability.md H2、H3、J1 |
| 5. 誠実さ | 確信度を正直に書いているか。事実に出典、意見に主体があるか。経験や動機が具体的か | constitution.md 第 5 条、第 10 条、第 11 条 |
| 6. 主張の裏付け | 主張を言い切るだけでなく、例やデータで示しているか。結びが根拠の範囲に収まっているか | constitution.md 第 12 条、expression.md X9 |

### 採点の基準

各観点を 0 から 100 で採点します。

| 点数 | 状態 |
|---|---|
| 95 以上 | 直すところが見当たらない |
| 90 から 94 | 小さな改善点はあるが、読み手の負担にはならない |
| 80 から 89 | 読み手が引っかかる箇所がはっきりある |
| 80 未満 | 構成か内容から直す必要がある |

- **合格**: すべての観点が 90 以上で、平均が 92 以上。
- 点数には、根拠となる行か抜粋を必ず添えます。根拠のない点数は無効です。
- 確かめられない観点 (事実の出典が手元にないなど) は点数を付けず「評価不能」とし、合格扱いにしません。
- ほかの観点の高さで、低い観点を相殺しません。

### 手順

1. 6 つの観点を採点し、根拠を書きます。
2. 不合格なら、最も低い観点から直します。直すときも revision.md の R1 と R2 を守ります。
3. 直した後に、もう一度検査 (inspection.md) と採点をします。
4. 直しは 2 回までにします。2 回直しても合格に届かない観点は、無理に点を上げず、残った課題として報告します。
   素材が足りないことが原因なら、それを書き手や依頼者に確かめる点として書きます。

書いた本人が採点すると甘くなりがちです。
別のエージェントやレビュー役を使える環境では、採点を本文を書いていない側に任せます。
使えない場合は、本文を初めて読む読み手として、見出しと各段落の最初の文だけを先に読み、骨格を確かめてから全体を読みます。

### 評価の報告

仕上げの評価は、依頼者が求めた場合か full モードのときに、次の形で添えます。

```text
自然さ 93 / 密度 91 / 見通し 94 / 論理 92 / 誠実さ 90 / 裏付け 92 (平均 92.0、合格)
最も低い観点: 誠実さ。3 段落目の「多くの利用者が」に出典がない (確認待ち)
```
