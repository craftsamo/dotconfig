# 診断と仕上げの評価

点数を使う場面は、既存文を書き換えずに評価する「診断」と、執筆・推敲した成果物を渡す前に点検する「仕上げの評価」の2つです。いずれのスコアも**読み手が払う処理コストと表現の偏り**を測る目安であり、書き手が人間か AI かを判定するものではありません（「AI が書いた」「人間が書いた」とは報告しない）。

## 診断

「この文章を採点して」「どこが不自然か診断して」のように、評価のみを求められた場合に使います。改めて書き直しを依頼されるまで原文は変更しません。

### 機械スコア

`scripts/inspect_text.py` の `naturalness` モードが以下の式で機械スコアを算出します。

```text
減点 = (critical × 8 + warn × 4 + info × 0.5) × 1000 / max(文字数, 1000)
機械スコア = max(100 − 減点, 20)
```

- 集計対象は `naturalness` の通常レーンのみです（experimental 規則や `reading-load`、`expression`、`notation` は機械スコアに含まれません）。
- 1,000字未満の短文は分母が 1,000 に固定されるため減点が小さく出ます。短文ではスコア帯より個別の指摘内容と実読の印象を重視します。
- 100字未満は採点対象外（`too_short`）、SudachiPy 未導入環境では `score.value` が `null`（`naturalness_unverified`）となります。`null` の場合は数値を捏造せず、未検査である旨と定性的な所見のみを報告します。

### 診断の深さとスコア調整

| 深さ | 手順 | スコアの扱い |
|---|---|---|
| quick（既定） | `naturalness`・`expression`・`reading-load` を実行し、目立つ偏りを確認する | 機械スコアを参考値としてそのまま示す |
| full | 全文を精読し、機械検査が拾いにくい問題（過剰な和語化 X11、行間のセルフ解説・予防線ラッシュ X12、具体性不足 X9、結論の後回し J1、主述のねじれ B2 など）も評価する | 機械スコアから ±15点の範囲で根拠付きで調整する |

- 指摘の大半が引用・定義済み専門用語・意図的な並列である場合は加点します。
- 機械スコアが高くても、専門語や漢語を不自然な和語・幼児語に崩している（expression.md X11）場合、単文のぶつ切りや行間のセルフ解説で不気味さが出ている（X7、X12）場合、一般論ばかりで論理やコロケーションが崩れている場合は減点します。

| 点数 | 帯（`score.band`） | 目安 |
|---|---|---|
| 90〜100 | `natural` | 目立つ型の偏りはなく自然に読める |
| 70〜89 | `minor` | 部分的な手直しでさらに読みやすくなる |
| 50〜69 | `needs_revision` | 表現の癖や構文の負担が目立つ |
| 0〜49 | `strong` | 構成や文体全体から見直す必要がある |

### 診断の報告形式

1. 総合: 点数、帯、診断の深さ（`full` で調整した場合は機械スコアと調整理由）。
2. 主な傾向: 検出された規則の件数と、読みづらさの原因になっているパターンの要約（該当する `expression.md` / `readability.md` の項目番号を添える）。
3. 気になる箇所: 最大5か所（行番号、短い抜粋、何が読み手の負担になっているか）。
4. 改善の方向性: どう直すとよいかの方針のみ（依頼されるまで全文の書き直しは出さない）。

## 仕上げの評価（6観点レビュー）

執筆・推敲した文章を渡す前の最終点検です。`quick` では頭の中で6観点を確認し、`full`（および依頼された場合）では各観点を 0〜100 点で採点します。

### 6つの観点

| 観点 | 点検する問い | 主な参照先 |
|---|---|---|
| 1. 自然さ | 定型句・翻訳調・紙芝居のような単文のぶつ切り・行間のセルフ解説がないか。専門用語や自然な漢語を不気味な和語・幼児語へ崩しておらず、語彙とコロケーションが読み手に馴染むか | expression.md（特に X1〜X7、X11、X12） |
| 2. 密度と簡潔さ | 一文ごとに実質的な情報があるか。前置き・同義反復・「〜という形」などの水増しがないか | constitution.md 第1条、readability.md D1・H1 |
| 3. 機能と見通し | 読み手が目的の情報へすぐ辿り着けるか。見出し・段落・箇条書き・表の使い分けが文書型に合っているか | constitution.md 第2条・第3条、genres.md、doctypes/*.md |
| 4. 論理の明確さ | 主張・理由・根拠のつながりが一読で追えるか。接続詞・主述対応・「の」の連鎖に破綻がないか | readability.md B2・C2・H2・H3・J1 |
| 5. 誠実さ | 断定・推測・未確認を正直に書き分けているか。事実に出典、意見に主体があり、捏造や勝手な留保削除がないか | constitution.md 第5条・第10条・第11条、revision.md R1・R2 |
| 6. 主張の裏付け | 主張を抽象語だけで済ませず、データ・コード・具体例で裏付けているか。結びが根拠の範囲内に収まっているか | constitution.md 第12条、expression.md X9 |

### 採点基準と合格ライン

| 点数 | 状態 |
|---|---|
| 95〜100 | 当該スコープ内で実質的な欠点がなく、目的に十分応えている |
| 90〜94 | そのまま実用になる水準。細かな改善余地はあるが読み手の負担にならない |
| 80〜89 | 読み手が引っかかる箇所（不自然な言い換え、曖昧な係り受け、冗長な前置きなど）が明確にあり修正が必要 |
| 80未満 | 構成・語彙選択・事実関係の維持に重大な問題があり、根本的な書き直しが必要 |

- **合格基準**: 適用されるすべての観点が 90点以上、かつ平均 92点以上（高い観点で90点未満の観点を相殺しない）。
- 各点数には必ず本文の該当箇所（引用または行・節）と理由を添えます。裏付け資料が手元になく検証できない観点は「評価不能」とし、点数でごまかしません。
- 不合格の場合は最も低い観点から修正して再検査・再採点します（手直しは最大2回までとし、材料不足が原因なら依頼者への確認事項として報告する）。
- レビュー用サブエージェントなどが使える環境では、執筆していない側に独立採点を任せます。

### 仕上げ評価の報告形式（full または依頼時）

```text
自然さ 94 / 密度 92 / 見通し 95 / 論理 93 / 誠実さ 91 / 裏付け 92（平均 92.8、合格）
最も低い観点: 誠実さ — 第3段落の移行期間が暫定値である旨の注記を補ったが、本番設定値は要確認
```
