# 表現のパターン

ここに挙げる型は文法上の誤りではありません。1回現れただけで機械的に消すのではなく、**中身の代わりに手癖の型が置かれていないか、頻度や文脈が読み手の邪魔をしていないか**で判断します。評価・留保・対比など実質的な意味を運んでいる語句はそのまま残してください。

特に注意すべきは、AI っぽさを消そうとして逆方向の不自然さ（X11 過剰な和語化と言い換えの暴走）に陥ることです。自然な漢語熟語や定着した専門用語は、そのまま使うのが最も読みやすい日本語になります。

### X1 決まり文句

前置き、締め、予防線としてどの文章にも差し込める定型フレーズです。

| 種類 | 代表的な形 |
| --- | --- |
| 前置き・予告 | 「さて、」「それでは、」「ここで注目したいのは」「〜について見ていきましょう」「解説していきます」「結論から言うと」「正直に言うと」「重要なのは」「ポイントは」「その経過を書き残しておきます」「まず時間帯です。」（見出し代わりの独立短文） |
| 締め・まとめ | 「このように」「まとめると」「総じて」「〜と言えるでしょう」「〜に他なりません」「いかがでしたか」「ぜひ試してみてください」 |
| 予防線 | 「あくまで一例ですが」「一概には言えません」「個人差がありますが」「〜のではないでしょうか」 |

- 直し方: 削っても意味が変わらない前置き・締めは削除します。「私たちは〜チームです。その経過を書き残しておきます」のような英語ブログ直訳の自己紹介と作業宣言は省き、きっかけや変化から自然に書き始めます。「まず時間帯です。」のように話題ラベルだけを1文にした箇所は、後ろの文と結んで主述のある文にします。「重要なのは〜」が実質的な評価を担っている場合は述語に移し、予防線は具体的な適用条件に書き換えます。
- 残す場合: 質問への直接回答で位置を示す「結論から言うと」、案内文の目的に沿った「ぜひご参加ください」、直後に具体的な条件分岐が続く「一概には言えません」などは残します。
- 検査: `forbidden_phrase`（naturalness）、`meta_filler`（expression）

### X2 誇張と空疎な語

具体性を伴わずに重要感や雰囲気だけを演出する語彙です。

| 種類 | 代表的な形 |
| --- | --- |
| 根拠なき強調 | 「非常に重要」「極めて重要」「まさしく」「不可欠」 |
| 空疎な形容 | 「根本的な」「核心的」「多角的」「包括的」「総合的」「鍵となる」「本質的」 |
| 雰囲気スロップ | 「手触り」「肌感」「温度感」「熱量」「解像度」「腹落ち」「地に足のついた」「等身大」「羅針盤」「起爆剤」「触媒」 |
| 壮大化 | 「真理」「境地」「美学」「深淵」「極致」「宿命」 |

- 直し方: 強調語を削り、何がどう影響するのかを事実や数値で書きます。雰囲気語は「何を調査し、何を明らかにするか」など実際の行動に置き換え、裏付けとなる事実が手元になければ確認事項とします（X9）。
- 残す場合: 字義どおりの用法（「画面の画素数・解像度」「熱量の単位」）や、分野の定義済み用語、依存対象を明示した「不可欠」は残します。
- 検査: `forbidden_phrase`（naturalness）、`slop_vocabulary`（expression）

### X3 翻訳調

英語の構文を語順だけ日本語に置き換えた冗長な組み立てです。

| 型 | 自然な形 |
| --- | --- |
| 「〜することができる」「〜することが可能です」 | 「〜できる」、可能動詞（「選べる」「戻せる」） |
| 「〜という点で」「〜という観点から」 | 「〜では」「〜で見ると」 |
| 「〜にとって重要」「〜にとって不可欠」 | 「〜には〜が必要」「〜は〜で決まる」 |
| 抽象名詞 + 「〜を持つ」 | 「〜がある」（例: 「大きな意味がある」） |
| 「〜することによって」 | 「〜して」「〜すれば」「〜で」 |
| 「それは〜だ。なぜなら〜からだ」 | 理由と結論を一文で結ぶか、理由から述べる |
| 文脈で自明な三人称代名詞（「彼女は〜」「彼は〜」） | 主語を省略するか、役割・名前で受ける |

- 直し方: 上表の簡潔な形に整えます。その際、「保存できます（可能）」と「保存します（動作・仕様）」の意味を取り違えないよう注意します。
- 残す場合: 規程・約款の定型（「〜することができる」）、定着した連語（「権限を持つ」「関心を持つ」）、複数の評価軸を明示する「費用の観点では」などは残します。
- 検査: `translationese`、`translationese_morph`、`english_syntax_cleft_because`（naturalness）

### X4 無生物主語と仕様の擬人化

抽象概念を主語にして作用動詞で受ける英文直訳構文や、ソフトウェア・モジュールに人間の認識・感情を持たせる擬人化です。

- 代表的な形:
  - 抽象主語: 「このことは〜をもたらす」「この事実は〜を証明する」「それが課題を浮き彫りにする」
  - 仕様・コードの擬人化: `このパッケージは取り置きを知らないので`、「この関数は空の引数を嫌う」「ログが悲鳴を上げている」
- 直し方: 抽象主語は「〜から〜が分かる」「〜ため〜が生じる」のように因果が追える文にします。仕様の擬人化は実際の技術的状態（「このパッケージは取り置きに未対応なため」「引数が空だと例外を送出する」）で書きます。
- 残す場合: ソフトウェアや仕組みの客観的な動作主体（「配信サーバーはメタデータを返します」「このコマンドは既存の設定を上書きします」）は技術文書として完全に自然なので直しません。
- 検査: `inanimate_subject_morph`、`english_syntax_inanimate_subject`（naturalness）、`metaphor_verb` の擬人化検出（expression）

### X5 比喩動詞と作業宣言

実際の挙動や調査内容を、曖昧な比喩動詞や「これから調べる」という宣言で済ませる型です。

| 種類 | 代表的な形 |
| --- | --- |
| 比喩動詞 | 「地味に効く」「データが静かに壊れる」「黙って無視される」「安全側に倒す」「時間を溶かす」「1つずつ潰す」「実装に踏み込む」「議論が収斂する」「前提が崩れる」「文化が醸成される」 |
| 作業の宣言 | 「深掘りする」「掘り下げる」「言語化する」「〜を探求する」「正面から扱う」 |

- 直し方: 実際に起きている現象（例: 「エラーを出さずに書きかけのファイルが残る」）で書きます。現象の詳細が原文から分からない場合は推測で具体化せず、原文を残すか確認事項にします。「深掘りする」「言語化する」は削り、中身から書き始めます。
- 残す場合: 一般的な慣用句（「骨が折れる」「腑に落ちる」）や、直前で具体的な現象を説明したあとでそれを受ける表現は残します。
- 検査: `metaphor_verb`（expression）、`forbidden_phrase`（naturalness）

### X6 否定→肯定の対比と思わせぶりな否定

「A ではなく B」「A だけでなく B も」を繰り返す型です。記事やエッセイでは「〜わけではない」「〜わけではありません」「A というより B に近い」「A とも B とも言わない」のように、**誰も誤解していない事柄をわざわざ一度否定してから述べる型**もよく現れます。

- 直し方: 読み手が実際に A と誤解する恐れがない箇所では、否定のクッションを外して事実や実感を直接書きます（例: 「当番表がなくなったわけではありません。月1回の更新に減らしました」→「当番表は月1回の更新に簡略化しました」）。「A だけでなく B も」を削るときに比重が変わらないよう注意します。
- 残す場合: 仕様の取り違え防止（「ミリ秒ではなく秒単位で指定します」「`.json` 付きではなく番号のみのパスにします」）など、否定自体に情報がある箇所は残します。
- 検査: `antithesis_repetition`（naturalness、3回以上で候補）

### X7 リズムの均質さと単文のぶつ切り

地の文で文長・文末・段落構成が機械的に揃いすぎている状態、または「一文一義」を「一文一述語（単文）」と誤解して**文の途中で毎回「。」と「です・ます」を押してしまう状態**です。

- 直し方:
  - 前提・属性を途中で言い切らない: 「当館は駅から徒歩5分の市立図書館です。平日は20時まで開館しています。」のように、同じ主語のひとまとまりの前提に毎回「〜です。」「〜ます。」と句点を打つと、箇条書きを読み上げているような稚拙なリズムになります。「当館は駅から徒歩5分の市立図書館で、平日は20時まで開館しています。」のように連用形（「〜で、」「〜し、」）で受け渡してください。素材メモから文章を起こすときも、メモの句点をそのまま完成文の切れ目にしません。
  - 背景→変化・行動→反応をつなぎ、後付けの説明単文を減らす: 「以前は毎朝ミーティングを開いていました。人数が増えるにつれて〜」は「以前は毎朝ミーティングを開いていましたが、人数が増えるにつれて〜」へ、「試しに文字を大きくしてみた。目が滑りにくくなった。」は「試しに文字を大きくしてみると、目が滑りにくくなった。」へ結びます。また、「質問箱を新設しました。誰でも投稿できる場所です。」のように直前の名詞を説明するだけの短い「〜です。」文を後ろに置かず、「誰でも投稿できる質問箱を新設しました。」と前の文に組み込みます。
  - 紙芝居リズム・分裂文の回避: 「駆け込んだのは、水曜の夕方だ。後輪の空気が抜けていると気づいた。このままでは駅まで歩けない。時刻は18時過ぎだった。」のように場面を短文や「〜したのは…だ」の分裂文に刻まず、「水曜の夕方、帰り道で後輪の空気が抜けていることに気づき、18時過ぎに商店街の自転車屋へ駆け込んだ。」と一息でつなぎます。
  - 文末と敬体の統一・絵日記調の回避: 回想やエッセイで `〜だった。`・`〜てみた。`・`〜くれた。` ばかりを並べると小学校の作文のように幼くなります。的確な動詞や場面内の現在形を交えて遠近感を出してください。また、「です・ます」調の途中で常体の現在形（「〜と後回しにしてしまう。」）や芝居がかった「〜たのです。」を混ぜず、1つの話題・場面は3〜5文程度の段落で受け止めます（1〜2文ごとに空行を入れない）。
- 残す場合: GitHub Issue・PR の要件一覧、仕様書、手順書、チェックリストなどの箇条書きでは、各項目の文末（「〜します」「〜する」など）が揃っているのが正しい姿です。単調さを避けるために箇条書きの文末をバラバラに変えてはいけません。
- 検査: naturalness のリズム系規則と expression の `sentence_end_repetition`・`choppy_sentence_run`（いずれも同一段落の地の文のみ対象）

### X8 語彙の使い回し

「対応する」「処理する」「実施する」のような曖昧な汎用動詞だけで別々の具体的な動作を済ませている状態です。

- 直し方: 「問い合わせに対応した」が「返信した」「修正した」「受付記録を残した」のどれを指すのか、実際の動作を表す動詞に書き分けます。
- 注意（過剰な言い換えの禁止）: 定義した専門用語や、「確認する」「追加する」「適用する」「保持する」のような意味の明確な漢語動詞を無理に言い換えないでください。変化をつけるためだけに「確かめる」「足す」「当てる」などへ置き換えると不自然になります（X11、readability.md I1）。
- 検査: `low_lexical_diversity_ttr`、`low_lexical_diversity_mtld`（naturalness、約4,000字以上の長文のみ）

### X9 具体性の不足

「側面」「観点」「重要性」「可能性」「あり方」「課題」などの抽象名詞ばかりが並び、固有名詞・数値・具体例がない状態です。

- 直し方: 言い回しをいじるのではなく、資料やコードから事実・数値・具体例を補います。手元に材料がなければ捏造せず、依頼者への確認事項として返します。
- 残す場合: 冒頭で文書の対象範囲を宣言する短い段落や、概念整理を目的とするエッセイの段落は残します。
- 検査: `low_specificity`（naturalness）

### X10 書式の過剰

太字、箇条書き、絵文字、定型のまとめ見出し、根拠のない「フェーズ1・ステップ2」などの装飾に頼りすぎている状態です。

- 直し方: 太字は要点の1か所に絞り、装飾絵文字は外します。因果関係のある経緯の箇条書きは地の文に戻し、「まとめ」見出しは削るか中身を表す見出しに変えます。
- 残す場合: 技術文書（Issue・PR・仕様書・手順書・リリースノート）やビジネス文書における要件・変更点・確認項目の箇条書きや表は、検索性と一覧性を高めるため積極的に使って構いません。
- 検査: `excess_bold`、`excess_list`（`tech`・`business` では停止）、`emoji`（expression）と naturalness の実験規則

### X11 過剰な和語化と言い換えの暴走

漢語熟語・カタカナ語・定型ラベルを避けようとするあまり、技術用語や自然な二字熟語を日常の和語（大和言葉）や幼児語、回りくどい説明句に崩してしまうパターンです。**読み手が頭の中で元の用語へ逆翻訳する負担が生じ、強い違和感（「気持ち悪い日本語」）の原因になります。**

| 崩れの種類 | 不自然な例（避ける） | 自然な実務・技術表現 |
| --- | --- | --- |
| ドメイン・技術用語の和語訳 | `道筋`、`部品`、`契約`、`山の版 / 札 / 段`、`生まれたばかり`、`焼かれる`、`配備` | `ルート / エンドポイント`、`パッケージ / モジュール`、`コントラクト`、`デッキ / カード / ティア`、`ミント直後`、`バーンされる`、`デプロイ` |
| 二字漢語の幼児語化 | `絵を配信する`、`フィールドを足す`、`変更を当てる`、`番号からカードをたどる` | `画像を配信する`、`フィールドを追加（付与）する`、`変更を適用する`、`トークン ID からカードを解決（参照）する` |
| 一般文・記事での作文調の平易化 | `引っかかることが出てきました`、`うまくいかなかったこともあります`、`前を通るだけだった` | `時間が分断される・形骸化が目立つ`、`弊害もありました`、`素通りするばかりだった・事足りていた` |
| 複合語を崩した説明句 | `止めて動かし直しても`、`状態を書き込む置き場`、`ふつうの引き`、`移転の記録`、`#39 の調べのコメント` | `再起動しても`、`状態の永続化ストア（保存先）`、`通常の抽選`、`Transfer ログ（転送記録）`、`#39 の調査コメント` |
| 「〜の形」の冗長な言い回し | `この形に直します`、`合う形に直します`、`変えられる形にし`、`残すという形です` | `この仕様に合わせて更新します`、`対応させます`、`変更可能にし`、`残しています` |
| 定型見出しの和語化 | `## 調べたこと`、`## 未決のこと`、`## 受け入れ` | `## 調査結果（現状）`、`## 未決事項`、`## 受け入れ条件` |
| コロケーションの崩れ | `ミントされたばかりは`、`期間が満ちた後は` | `ミント直後は`、`確定期間の経過後は` |

- 直し方: その分野の実務者やエンジニアが普段そのまま使う漢語熟語・カタカナ語・英語識別子に戻します。「A の B の C の D」と「の」を連ねず、「スナップショット時点」「カード定義 JSON」「確定済みブロック」のように自然な複合語を使ってください。
- 残す場合: 子どもや日本語を母語としない読者向けに「やさしい日本語」で書くよう明示的に指定された文書（references/genres.md）のみ例外とします。
- 検査: `unnatural_paraphrase`（expression）と、派生する「の」の連鎖に対する `no_chain`（reading-load）

### X12 行間のセルフ解説と過剰な予防線

エッセイや実践記事で、具体的な会話・行動・出来事を書いた直後に**その意味や余韻を書き手自身で答え合わせしてしまう癖**と、**末尾に免責事項を何文も積み上げる癖**です。AI 生成文特有の「鼻につくわざとらしさ」「言い訳がましさ」の主因になります。

- 避けるパターン:
  - 行間の答え合わせ: 具体的な台詞や場面のあとに「タイヤの買い替えも勧めないし、余計な愛想も言わない。いま必要な手入れだけをしてもらった気がした」「ただ静かな時間が流れていた」のように、読み手が場面から自然に受け取れるニュアンスをわざわざ言語化して添える。
  - 自明な事情の補足: 「後輪の空気が抜けていると気づいた。このままでは遠くまで走れない。」「用事がなければ寄らない場所だから、これまで縁がなかったのだと思う。」のように、文脈から明らかな理屈を説明文として挟む。
  - 末尾の免責ラッシュ: 体験記やチームの実践記事の終盤で、「もちろん万能ではありません」「規模が変われば別です」「向かない組織もあります」「これからも変わるかもしれません」と予防線を何文も連ねる。
- 直し方: 会話や具体的な行動を書いたら、解説を足さず事実や次の動作で止めます。実践記事の前提条件（「少人数の窓口での運用ですが」など）は、冒頭や該当箇所で1文だけ自然に添え、末尾の言い訳段落は丸ごと削ります。
- 残す場合: 仕様書・契約・運用ガイドにおける明示的な制限事項・非対象範囲の記述や、分析レポートでデータから導かれる考察を述べる箇所は本来の役割なので残します。

## 事例

### 事例1: 技術 Issue の要件記述（X4、X11、C2 の改善）

Before（過剰な和語化・擬人化・「の」の連鎖）:

> ## 調べたこと
> - 配信サーバーは、番号から札をたどり、山の版 (#50) のカードの JSON に `name` と `image` を足して返します。`image` はカードの絵を指します。
> - リビールのパッケージ (#40) は取り置きを知らないので、この例外をパッケージに足し、合う形に直します。
> - 止めて動かし直しても同じ状態に戻ります。状態を書き込む置き場は作りません。

After（自然な技術日本語・敬体）:

> ## 調査結果
> - 配信サーバーはトークン ID から対応するカードを解決し、カード定義（#50）の JSON に `name` と `image` を追加して返します。`image` はカード画像を指します。

### 事例3: エッセイ・体験記の呼吸と行間（X6、X7、X12 の改善）

> 店主はバルブを外し、「虫ゴムが切れてるね」とだけ言った。タイヤの交換も勧めないし、余計な愛想も言わない。いま必要なことだけをしてもらった気がした。特別な店を見つけたわけではないが、また寄ろうと思った。
