# 表現のパターン

## 前提

ここに挙げる型は、日本語の誤りではありません。
1 回だけ使われた「このように」や「ではなく」は、たいてい問題になりません。
読み手の負担になるかどうかは、頻度と文脈で決まります。
同じ型が段落ごとに現れる、中身の代わりに型が置かれている、という状態を探します。

意味を運んでいる語は残します。
評価、留保、対比、時間の変化を担っている言い回しを、型に似ているという理由で消しません。
決まり文句を別の決まり文句に置き換えても、読み手の負担は減りません。
「このように」を「以上のことから」にするのではなく、その文が何を伝えるべきかから書き直します。

書き手が個別に避けたい語は、スタイルプロファイル (assets/style-profile-template.md) に記録します。
そこに書かれた好みは、その書き手と文書に限った指定です。
一般の禁止語として、ほかの文書に広げません。

各項目の「検査」は、インスペクターのどの規則がその型を候補として挙げるかを示します。
規則名に「実験」とあるものは、要求に `"experimental": true` を付けたときだけ動きます。
候補が出ても修正の義務はなく、候補が出なくても型がないとは限りません。

## 各パターン

### X1 決まり文句

前置き、締め、予防線として、どの文章にも差し込める言い回しです。

| 種類 | 代表的な形 |
| --- | --- |
| 前置き・予告 | 「さて、」「それでは、」「ここで注目したいのは」「〜について見ていきましょう」「解説していきます」「結論から言うと」「正直に言うと」「重要なのは」「ポイントは」 |
| 締め・まとめ | 「このように」「まとめると」「総じて」「〜と言えるでしょう」「〜に他なりません」「いかがでしたか」「ぜひ試してみてください」 |
| 予防線 | 「あくまで一例ですが」「一概には言えません」「個人差がありますが」「〜のではないでしょうか」 |

読み手の負担: 情報のない語を読む時間が増えます。
前置きが続くと、読み手は本題がどこから始まるかを探しながら読むことになります。
予防線が重なると、書き手が何を確かめ、何を確かめていないのかが見えなくなります。

直し方: 削っても主張が変わらなければ削ります。
「重要なのは」が評価を担っているなら、評価を述語へ移します (「締め切りの前日に確認するのが最優先です」)。
予防線は、言い切れない理由や条件そのものに置き換えます (「築 30 年を超える建物には当てはまりません」)。
締めの一文は、本文で言い終えていれば消し、言い終えていなければ本文を直します。

残す場合: 問いに直接答える文書での「結論から言うと」は、答えの位置を示す役目を果たします。
参加を呼びかける案内文の「ぜひご参加ください」は、文書の目的そのものです。
条件を続けて書く「一概には言えません」は、予防線ではなく前置きとして働きます。
「重要なのは」「ポイントは」「さて、」「このように」「不可欠」は日常の文章でもよく使うため、naturalness は info として扱います。
expression モードの `meta_filler` は文頭の前置きとしての「重要なのは」を warn で返しますが、評価を担う用法なら残します。

検査: `forbidden_phrase` (naturalness) と `meta_filler` (expression)。

### X2 誇張と空疎な語

強さや深さの感触だけを足し、何がどう重要なのかを言わない語です。

| 種類 | 代表的な形 |
| --- | --- |
| 強調 | 「非常に重要」「極めて重要」「まさしく」「不可欠」 |
| 空疎な形容 | 「根本的な」「核心的」「多角的」「包括的」「総合的」「鍵となる」「本質的」 |
| 雰囲気語 | 「手触り」「肌感」「温度感」「熱量」「解像度」「腹落ち」「地に足のついた」「等身大」「羅針盤」「起爆剤」「触媒」 |
| 壮大化 | 「真理」「境地」「美学」「深淵」「極致」「宿命」 |

読み手の負担: すべてが「極めて重要」なら、どれがいちばん重要かを読み手が決め直すことになります。
「多角的に検討した」は、どの角度から見たのかを読み手に想像させます。
小さな出来事に「真理」や「宿命」を当てると、読み手は誇張を差し引いて読むようになり、ほかの記述まで疑います。

直し方: 強調語の代わりに、重要だと言える根拠を書きます (守らないと何が起きるか、何と比べて大きいか)。
「解像度を上げる」は、実際に何を調べ、何が分かったかに置き換えます。
根拠や中身が原文にも文脈にもなければ、作らずに書き手へ確認します (X9)。

残す場合: 字義どおりの用法は対象外です (「画面の解像度」「体温を測る」「熱量の単位」「建物の土台」)。
その分野で定義された用語 (UX 調査の「メンタルモデル」など) も残します。
「不可欠」は、何が何に依存しているかを同じ文で述べているなら残します。

検査: `forbidden_phrase` (naturalness、X2 に分類された語) と `slop_vocabulary` (expression)。

### X3 翻訳調

英語の構文を語順だけ日本語にしたような組み立てです。

| 型 | 短くした例 |
| --- | --- |
| 「〜することができる」「〜することが可能です」 | 「〜できる」、可能形 (「選べる」「戻せる」) |
| 「〜という点で」「〜という観点から」 | 「〜では」「〜で見ると」 |
| 「〜にとって重要」「〜にとって不可欠」 | 「〜には〜が要る」「〜は〜で決まる」 |
| 抽象名詞を目的語にした「〜を持つ」 | 「〜がある」 (「大きな意味がある」) |
| 「〜することによって」 | 「〜して」「〜すれば」 |
| 「〜であることは間違いない」「〜に他ならない」 | 根拠を先に書き、普通に言い切る |
| 「それは〜だ。なぜなら〜からだ」 | 理由と結論を 1 文にするか、理由から書く |
| ダッシュで挟んだ挿入 | 括弧にするか、文を分ける |

読み手の負担: 文が長くなるわりに情報は増えません。
読み手は、日本語として素直な形に頭の中で組み直しながら読むことになります。

直し方: 上の表の短い形にします。
置き換えた結果、可能と事実の区別が変わらないかを確かめます (「保存できます」と「保存します」は意味が違います)。

残す場合: 法令や規程の文体では「〜することができる」が定型として使われます。
「関心を持つ」「権限を持つ」のように定着した組み合わせの「持つ」は自然です。
複数の評価軸を並べる文書の「費用の点では」「安全の観点では」は、軸を示す役目があれば残します。

検査: `translationese` と `translationese_morph` (naturalness)、`english_syntax_cleft_because` (naturalness、実験)。

### X4 無生物主語

意志を持たないものを主語に立て、他動詞や感情の動詞で受ける形です。

形: 「このことは〜をもたらす」「この事実は〜を証明する」「それが〜を浮き彫りにする」「数字が物語っている」のように、抽象的な主語が判断や作用を担います。
擬人化の形として、「ログが悲鳴を上げている」「この関数は引数を嫌う」のように、物に感情や意図を持たせる言い方もあります。

読み手の負担: 誰が判断したのか、何が原因なのかが文から消えます。
擬人化は、プログラムや制度が自分で望んで動いているかのように読め、因果を取り違えさせます。

直し方: 判断した人や状況を主語にするか、「〜から〜が分かる」の形にします。
擬人化は、実際に起きている状態や条件に置き換えます (「ログに同じエラーが毎秒記録されている」「この関数は引数が空だと例外を出す」)。

残す場合: ソフトウェアや仕組みの働きを客観的に述べる文は、そのままで構いません。
「ツールがログを収集します」「このコマンドは既存の設定を上書きします」は、Microsoft の日本語スタイルガイドの考え方でも自然な説明です。
主語を省いた受け身 (「ログは 7 日後に削除されます」) も、動作主が読み手にとって重要でなければ適切です。
直すのは、物に感情や意図を持たせている場合と、判断の主体が分からなくなっている場合だけです。

検査: `inanimate_subject_morph` と `english_syntax_inanimate_subject` (naturalness)。
検査は「これ」「それ」「こと」「事実」などの主語と、「示す」「もたらす」「意味する」などの動詞の組み合わせだけを拾います。

### X5 比喩動詞と飾り語

起きていることを、比喩の動詞や作業の宣言で言い表す型です。

| 種類 | 代表的な形 |
| --- | --- |
| 比喩動詞 | 「地味に効く」「データが静かに壊れる」「黙って無視される」「安全側に倒す」「時間を溶かす」「1 つずつ潰す」「実装に踏み込む」「議論が収斂する」「〜した瞬間」「前提が崩れる」「文化が醸成される」 |
| 作業の宣言 | 「深掘りする」「掘り下げる」「言語化する」「〜を探求する」「正面から扱う」 |

読み手の負担: 比喩は、何がどうなったかを読み手の推測に任せます。
「静かに壊れる」だけでは、値が欠けるのか、古い値が残るのか、読めなくなるのかが分かりません。
「深掘りする」と宣言しても、何を調べたかは次の文まで分かりません。

直し方: 比喩が指していた出来事や結果を、文脈にある情報で書きます。
比喩が運んでいた含みは残します (「地味に」の目立たないが確かな効果、「溶かす」の後悔)。
作業の宣言は削り、調べた中身から書き始めます。
出来事が文脈から分からなければ、推測で具体化せず書き手に確認します。

残す場合: 定着した慣用句は残します (「手を焼く」「骨が折れる」「腑に落ちる」)。
字義どおりの用法も対象外です (「薬が効く」「時計が壊れる」「雪が溶ける」)。
直前で現象を説明したあと、その説明を受ける短い言い方として使う比喩は、読み手の負担になりません。

検査: `metaphor_verb` (expression)、`forbidden_phrase` (naturalness、X5 に分類された語)。

### X6 否定→肯定の対比

「A ではなく B」「A だけでなく B も」「A というより B」で言いたいことを示す型です。

読み手の負担: 対比は、読み手が A だと思っている前提で書かれます。
誰も A だと思っていなければ、読み手は存在しない誤解を一度受け取ってから捨てることになります。
同じ型が続くと、内容より構文の反復が目に付きます。

直し方: A が実際の誤解でなければ、B を直接述べます。
対比を残す箇所は、読み手が本当に A を想定しやすい 1 か所に絞ります。
否定を外すときに「A に加えて B」や「A より B」へ変えると、元の文の比重が変わります。

残す場合: よくある誤解を正す文、仕様の取り違えを防ぐ文は残します (「タイムアウトは秒ではなくミリ秒で指定します」)。
否定そのものが主張である場合も残し、言い回しだけを整えます。

検査: `antithesis_repetition` (naturalness)。
「ではなく」「だけでなく〜も」が 3 回以上あると候補になり、文数に対する割合で重さが上がります。
2 回以下は検査が拾わないため、読んで判断します。

### X7 リズムの均質さ

文の長さ、文末、段落の大きさがそろいすぎている状態です。

形: どの文もほぼ同じ長さで、隣り合う文の長さまで連動しています。
「〜です。〜です。〜です。」のように同じ文末が 3 文以上続きます。
どの段落も同じ文数で、文頭の言葉や品詞の並びが繰り返されます。

読み手の負担: 内容の重さが形に表れないため、どこが要点かを読み手が自分で探すことになります。

直し方: 長さは内容の重さで決めます。
要点は短い文で言い切り、補足は前後の文にまとめます。
軽い話題は 1 文の段落で済ませ、込み入った話題には段落を多く使います。
文末を変えるのは、内容に合う別の形 (過去、状態、問い、体言止め) があるときだけです。
文末をそろえ直すために、敬体と常体を混ぜたり、勧めを義務に変えたりしません。

残す場合: 手順書の「〜します」の連続、規則の列挙、意図した並列、製品名で始まる文の連続は、そろっているほうが読みやすくなります。

体言止めについての注意: `nominal_ending` は、長い文章に体言止めが 1 つもないことを知らせる規則で、使いすぎは数えません。
候補が出ても体言止めを足す義務はなく、地の文で多用すれば文の続きが予測できず読み手が疲れます。

検査: naturalness の `low_sentence_variance`、`low_burstiness`、`high_length_autocorrelation`、`nominal_ending`、`uniform_paragraph_structure`、`repeated_sentence_lead`、`repeated_syntax_template` と、expression の `sentence_end_repetition`。
このうち `high_length_autocorrelation` と `repeated_syntax_template` は実験です。

### X8 語彙の使い回し

「対応」「実施」「活用」「確認」のような汎用の語が、異なる動作をまとめて引き受けている状態です。

読み手の負担: 「問い合わせに対応した」が、返信したのか、直したのか、受け付けただけなのかが読み取れません。
同じ語が続くと、別々の出来事が同じものに見えます。

直し方: 動作ごとに、その動作だけを指す動詞を選びます (「返信した」「修理した」「受け付けた」)。
同じことを言い直しているだけの文は削ります。

残す場合: 定義した用語、製品名、画面の項目名は、同じ語で通します。
言い換えて変化を付けると、読み手は別の概念だと受け取ります (readability.md I1、J2)。
エッセイで意図して繰り返す語句も残します。

検査: `low_lexical_diversity_ttr` と `low_lexical_diversity_mtld` (naturalness)。
本文が約 4000 字に満たない場合は判定しません。

### X9 具体性の不足

「側面」「観点」「重要性」「可能性」「あり方」「課題」のような抽象名詞が並び、固有名詞、数値、実例がない段落です。

読み手の負担: 読み終えても、何をすればよいか、何が起きたかが手元に残りません。

直し方: これは文体の問題ではなく、材料の不足です。
言い回しを整えても具体性は増えないため、原文の資料や前後の文脈から事実を集めます。
見つからなければ、書き手に確認する点として返します (何の数値か、どの事例か)。
数値、名前、事例を推測で作りません。

残す場合: 文書の冒頭で範囲を示す段落や、考えそのものを扱うエッセイの段落は、抽象的でかまいません。

検査: `low_specificity` (naturalness)。
80 字以上の段落ごとに、固有名詞、数量、例示の語と抽象名詞の割合を比べます。

### X10 書式の過剰

太字、箇条書き、絵文字、定型の見出しや段階番号が、文章の役目を肩代わりしている状態です。

| 種類 | 代表的な形 |
| --- | --- |
| 太字 | 段落ごとに複数の太字がある |
| 箇条書き | 理由や経緯まで箇条書きにして、接続詞が消えている |
| 絵文字・記号 | 見出しや文頭の絵文字、装飾の記号 |
| 定型の見出し | 「まとめ」「おわりに」「結論」で、本文の言い直しだけが続く |
| 段階番号 | 順序や区切りのない内容に「フェーズ 1」「ステップ 2」を付ける |

読み手の負担: 強調が多いと、どれも強調として働かなくなります。
箇条書きでは「なぜなら」「そのため」が落ち、項目の関係を読み手が組み立て直すことになります。
絵文字は意味が一定でなく、読み上げ環境では名前がそのまま読まれます。
定型の見出しは、その節に何があるかを伝えません。
段階番号は、実際にはない順序や関門を読み手に想像させます。

直し方: 太字は、見落とすと困る 1 点 (警告、期限) に絞ります。
理由や経緯の箇条書きは、接続詞を補って文章に戻します。
絵文字は言葉に置き換えます。
見出しは中身で名付けます (「まとめ」ではなく「残る課題と次の作業」)。
番号は、本当に順序がある作業にだけ付けます。

残す場合: 並列の項目、手順、比較、チェックリスト、リリースノートは、箇条書きや表のほうが速く読めます。
ビジネス文書では書式の多さが検索や判断を助けることが多く、検査も一部の規則を止めます (genres.md)。
太字が表示されない書き方 (`bold_not_rendered`) は表記の問題として notation.md で扱います。

検査: `excess_bold`、`excess_list`、`emoji` (expression)、`high_bold_density`、`high_bullet_ratio`、`boilerplate_heading`、`numbered_phase_structure`、`high_emoji_symbol_density` (naturalness、いずれも実験)。

## 事例

### 事例 1: 図書館の開館時間のお知らせ

Before:

> さて、今回は夜間開館について見ていきましょう。
> 夜間開館は、単なる時間延長ではなく、地域の学びを支える非常に重要な取り組みです。
> 利用者の声だけでなく職員の働き方も踏まえて、包括的な検討を行いました。
> このように、夜間開館は地域にとって不可欠な存在と言えるでしょう。

After:

> 4 月から、水曜と金曜は閉館時刻を 17 時から 20 時に延ばします。
> 仕事帰りに本を返せないという声が、昨年のアンケートでいちばん多かったためです。
> 職員は早番と遅番に分かれるため、1 人あたりの勤務時間は変わりません。

変えた理由: 前置き、締め、対比 2 回、強調語を除くと、Before には伝える事実がほとんど残りませんでした (X1、X2、X6、X9)。
曜日、時刻、理由、勤務の扱いは文体からは出てこないため、担当者に確認してから書きました。
確認できなければ、本文を飾り直さず、確認したい点として返します。

### 事例 2: 写真のバックアップスクリプトの説明

Before:

> このスクリプトは、写真フォルダーの差分を検出することができます。
> この仕組みは、ストレージ容量の大幅な節約をもたらします。
> ただし、外付けディスクが途中で外れると、バックアップが静かに壊れます。

After:

> このスクリプトは、前回のバックアップ以降に追加・変更された写真だけをコピーします。
> 全件をコピーし直さないため、バックアップ先の使用量が増えにくくなります。
> ただし、コピーの途中で外付けディスクが外れると、書きかけのファイルが残ったまま終了し、エラーは表示されません。

変えた理由: 1 文目の「このスクリプトは」は動作の客観的な説明なので主語を残しました (X4)。
「〜することができる」と「差分」は、書き手の README にあった実際の動作に置き換えました (X3)。
2 文目は抽象主語の「仕組みが節約をもたらす」を理由と結果の形にし、数値のない「大幅な」を削りました (X4、X2)。
「静かに壊れる」は、書き手のログにあった挙動 (書きかけのファイルが残り、終了コードは 0) で具体化しました (X5)。
挙動が分からない場合は「静かに」を残し、何が起きるのかを書き手に確認します。

### 事例 3: 合唱団に入って半年のエッセイ

Before:

> 合唱団に入って半年が経ちました。
> 毎週土曜日の朝に練習があります。
> 最初の 2 か月は声がほとんど出ませんでした。
> 隣の人の息継ぎに合わせるようにしました。
> すると低い音が出るようになりました。
> 私はそこで音楽の真理に触れました。
> 皆さんもぜひ試してみてください。

After:

> 合唱団に入って半年になります。
> 土曜の朝の練習で、最初の 2 か月はほとんど声が出ませんでした。
> 変わったのは、隣の人が息を吸うのに合わせて、自分も吸うようにしてからです。
> それから、低い音が出るようになりました。
> 歌うことの手応えを、そのとき初めてつかみました。

変えた理由: 短い文が同じ長さと同じ文末で並んでいたため、出来事の重さに合わせて長短を付けました (X7)。
「真理に触れた」は体験に対して大きすぎる語なので、言い切りの強さは保ったまま、書き手が感じた発見の範囲に戻しました (X2)。
締めの呼びかけは本文と関係がないため削りました (X1)。
教訓でまとめず発見の一文で終え、Before にない出来事や感覚は足していません (genres.md)。
