# 診断モード（score）：書き換えずに、AI 臭さをスコアと理由で返す

診断モードでは文書を一切書き換えません。
返すのは、スコア、その根拠、直すなら何からかの3点です。
「この文章、AI っぽい?」「どれくらい AI 臭いか採点して」という依頼に応えるモードで、リライトを求められたら通常の検査ループ（SKILL.md の Workflow）へ切り替えます。

## 2段階の深さ

- **quick（既定）**：`scripts/lint.py --json`（ジャンルがわかれば `--genre` つき）を1回実行し、スケルトンを一瞥する。
  30秒程度で終える。
- **full**：quick に加えて `scripts/outline.py` と `scripts/terms.py` を実行し、構造レビューと読みやすさレビューの所見（`revision.md` の観点）を判断に織り込む。
  対象の文書型が定まっている場合は `japanese-business-docs` の doctype 照合も行う。
  診断では収束ループを回さず、1周の評価で完結させる。
  数分かかる。

## スコアの算出：機械ベース + 判断調整の二層

スコアは0〜100の自然度で、**高いほど自然（AI 臭が薄い）**です。
ユーザーへ返すときも、この向きを一言添えます。
二層で作り、内訳を必ず開示します。

**機械ベース（決定的）**：100点から、lint findings を文書長で正規化して減点します。

```
減点 = (critical×8 + warn×4 + info×0.5) × (1000 / max(文書の文字数, 1000))
機械ベース = max(100 − 減点, 20)
```

文書の文字数は本文全体の文字数で、改行や Markdown 記法込みの len で構いません（目安の正規化なので厳密さは要りません）。
短い文書ほど1件の重みが大きく、長い文書では密度で効く設計です。
本文が空か実質空（100字未満）の場合はスコアを出さず、「診断対象として短すぎる」と返します。

**判断調整（±15点の範囲）**：full では、構造レビューと読みやすさレビューの所見で調整します。
lint に拾えない構造の AI 臭（全節同型、フラット列挙、確信度の平坦化、So What の空洞、順序、段階の押し付け）は減点し、lint が誤検知気味でも文脈上自然と判断した findings は減点を戻します。
quick では調整せず、機械ベースをそのまま使います。
そのぶん「quick の精度は粗い」と明記して返します。
調整後の最終スコアは0〜100に切り詰めます。
最終スコアは min(max(スコア, 0), 100) とします。
機械ベースが100のとき加点調整しても100を超えません。

スコアは判断を含む目安であり、同じ文書でも数点は揺れます。
CI のゲートに使う数値ではありません。
この注意は結果に一言添えます。

## バンドと言い方

| スコア | バンド | 伝え方の例 |
|---|---|---|
| 90〜100 | 自然 | AI 臭はほぼ見当たらない。指摘があっても好みの範囲 |
| 70〜89 | 軽微 | 数カ所に癖が残るが、読者が「AI っぽい」と感じる可能性は低い |
| 50〜69 | 要修正 | 表層か構造のどちらかに明確な AI 臭がある。直す価値がある |
| 0〜49 | 濃厚 | 複数のカテゴリで強く検出。リライト推奨 |

## 出力の形式

1. **スコアとバンド**（機械ベースと判断調整の内訳つき）を示す。
2. **理由トップ3〜5**：カテゴリ名でなく中身で書く。「『〜ではなく』の対比が全文の4%で機械的なリズムになっている（L12 ほか）」のように、代表箇所の行番号と、なぜそれが AI 臭なのかを一言で書く。
3. **直すなら何から**：効果の大きい順に2〜3個挙げる。
   ただし診断モードでは直さない。
   「リライトしますか」と添えて終える。

理由は lint の detail の転記ではなく、文書の文脈に即して言い直します。
findings が多い場合もすべては列挙せず、スコアを最も動かしたものに絞ります（フラットな列挙はここでも避けます）。
