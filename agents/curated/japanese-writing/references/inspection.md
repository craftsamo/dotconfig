# 記事の検査

## 目的と範囲

検査は、読み直す箇所を探すために使います。誤字校正器でも、文章品質や AI 生成を判定する装置でもありません。
語の出現頻度や書式の多さだけでは、修正の理由になりません。
短い案内文や校正だけの依頼に、記事の構成変更を要求しません。

## 実行

実行可能な環境では、スキルのルートを基準に次のコマンドを使います。
`PYTHON` は管理者が依存を準備した Python 3.10 以降の実行ファイルです。
`request.json` は呼び出し側が扱う入力であり、検査器自身はファイルを作りません。

```sh
"$PYTHON" -I -B scripts/inspect_text.py --request < request.json
```

```json
{"text":"保存先を選べるようになりました。","modes":["reading-load","terms"]}
```

受け付けるフィールドは `text` と `modes` だけです。`modes` を省略すると全モード、空配列なら検査なしです。
本文は UTF-8 で131072バイト以下、要求全体は1 MiB 以下です。上限超過はエラーになり、無言で本文を切り詰めません。
専用の読み取りツールがある呼び出し側は、シェルを使わず同じ本文とモードを渡します。
検査器はネットワーク、原文の変更、インストールを行いません。ただし、呼び出し側の会話履歴に入力が保存される可能性はあります。

| モード | 返す情報 | 判断しないこと |
| --- | --- | --- |
| `reading-load` | 90文字を超える文候補、7文字以上の漢字連続、近接した格助詞「の」、二重否定の候補 | 文法的な誤りや修正の必要性 |
| `outline` | 見出しと段落冒頭の物理行 | 論理の正しさ、必要な構成 |
| `terms` | カタカナ語、英字略語、形態素解析による固有名詞の候補と出現回数 | 読者が知っているか、説明が十分か |
| `structure` | 太字、箇条書き、見出し、まとめに相当する見出しの件数と割合 | 多すぎるか、文章品質が高いか |

読み取り専用 CLI の終了コード `0` は実行成功です。指摘なしや品質の合格を意味しません。
`status: partial` でも終了コードは `0` です。入力エラーや実行失敗は非ゼロになります。

## 結果の確認

`input_sha256` は渡した本文の UTF-8 バイト列に対応します。`inspector_version` と `dependencies` は検査器と依存の版です。
`executed` は実行した検査 ID、`unverified` は未検査の項目と理由です。
SudachiPy と辞書の版が `scripts/requirements.txt` と一致しない場合、形態素解析に依存する検査だけを未検査として返します。
それ以外の候補が返っていても、全検査が済んだとは扱いません。

行番号・列番号は渡した本文に対する1始まりの文字位置です。抜粋は原文の一部です。
ファイル読み取りツールの行番号接頭辞や表示用ラッパーを本文へ混ぜません。
本文を再入力する際に要約や表記修正をせず、読めていない全文を再構成しません。
抜粋を検査する場合は、元の範囲と行番号の対応を記録し、全文の検査や全文の割合とは報告しません。
ハッシュだけでは、入力が元ファイル全体と一致する証明にはなりません。

`truncation` には総件数、返却件数、省略件数などが入ります。
候補は最大100件、構成と用語は各200件、抜粋は各240文字です。返却量の上限による追加省略も明示されます。
`status: partial`、未検査項目、省略のある結果を完全な検査結果と呼びません。
呼び出し側がさらに出力を切り詰めた場合も、失われた結果を推測しません。

指摘ごとに原文と必要な前後関係を読み、具体的な問題と修正範囲を確かめます。
実際に修正した後は、変更に関係するモードだけを再確認します。
変更前の結果で変更後の文章を確認済みとせず、候補がなくなるまでの反復を義務にしません。
必須の検査ができなかった場合は、その条件を未確認として呼び出し側へ返します。

## 修正と保持の例

| 観察 | 判断 |
| --- | --- |
| 「担当部署別対応状況一覧」という漢字連続 | 正式な帳票名なら残す。説明文なら、部署ごとの対応状況を示す一覧であることが伝わる形を検討する |
| 「実施できないわけではありません」という二重否定 | 留保を表すので「実施できます」に変えない。何が曖昧かを確認する |
| 「会社の部門の担当者の連絡先」の助詞連続 | 関係が明確なら保持する。関係を取り違えやすい場合だけ説明を補う |
| 長い文に適用条件と例外が含まれる | 条件と例外を残して分割できるか検討する。短くするために削除しない |
| 太字や箇条書きが多い | 比較・検索・手順確認に役立つなら残す。数字だけで段落へ戻さない |
| 冒頭と末尾が同じ説明を繰り返す | 末尾が判断や確認に役立つ要約か、情報を増やさない言い直しかを読む |
| 「キャッシュ」が用語一覧に出る | 読者と前後の説明を確認する。「一覧に出た＝未説明」ではない |

## 解析上の限界

Markdown は限定的な行ベースの解析です。コード、引用、表、先頭の frontmatter、コメントを除きます。
読解負荷は地の文、用語と書式は見出し・箇条書きも対象です。
インラインコードやリンク先などをマスクし、除外箇所をまたいで形態素をつなげません。
箇条書きの継続行は対象行数に含めますが、箇条書き件数はマーカーのある行だけを数えます。
書式の文字数には残った Markdown 記号が含まれます。割合の分母は結果に明示します。

複雑な入れ子、複数行にまたがるインライン構文、一般の HTML ブロックには完全対応していません。
文候補は物理改行で区切るため、折り返された長文を過小に数える場合があります。
形態素解析へ渡す単一区間が40000バイトを超える場合、その区間は未検査になります。
まとめ見出しは語頭による候補抽出であり、意味の分類ではありません。
これらに該当する文章は直接読み、必要なら元の範囲を明示した本文抜粋を使います。
