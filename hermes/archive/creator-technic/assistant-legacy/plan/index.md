# Legacy creative - decided production units

Use ONLY when Creator confirms that the request needs a retained legacy
method and assistant-side unit decisions. Start at [Client plan](../../SKILL.md)
otherwise. A missing Client guide does not establish a legacy route. A served
failure or unsupported field is a finding, never permission to switch methods.
Confirm any change of purpose, cost, locality or requested method with the user.

These references retain old capabilities, not a house style. Design choices
come from this job's purpose, supplied references and user decisions. When
useful, use [reference research](../reference-research.md); it is not a
mandatory preliminary phase. Ask Creator to ground engine behavior in its
current production contract rather than importing rules from a past film.

## Units

| Unit | Releases with | Role |
| --- | --- | --- |
| Anchor | settled direction and a sanctioned sample allowance | lock identity or direction before a dependent batch; respect required user approval |
| Part | complete family spec, input paths and Budget | one asset or one anchored batch |
| Assembly | fixed edit spec and QA-passed part paths | deterministic combination of verified parts |

A single asset is one Part, not a compulsory three-stage project. Use
[asset-set.md](asset-set.md) for consistent batches and
[composite-media.md](composite-media.md) for parts feeding an assembly.

## Release decisions

- Set purpose, audience, destination, quantity, deadline, done criteria and
  invariants from the user and current context, not a stored genre template.
- Carry a `Budget:` line per released unit. Ask Creator for the effective
  allowance of its chosen legacy contract; do not reuse hands defaults or
  spend a presumed allowance. Expansion stays within what the user sanctioned.
- Where the method offers multiple backends, settle `Backend:` with Creator.
  A backend change crossing cost, locality or runtime boundaries returns to
  Plan. It is not an execution-time fallback.
- Read the selected family below and resolve its open decisions before
  releasing that unit. Infer what the user already supplied; batch only the
  remaining essential questions. Feasibility and costs come from Creator,
  never an unverified reference example.

The result is an ordered set of released units, not a whole-job brief for
Creator to decompose under this old contract. Continue through
[legacy execution](../../../execute-assistant-creative/references/legacy/index.md). For a served
dependency such as speech, use the normal Creator Client handoff and consume
its accepted output; do not invent an Assistant-owned speech unit.
