# Marketing capability — plan / execute / qa

Load for campaign work and outbound publishing: X posts/threads via xurl,
content strategy and calendars, honest critique of assets and drafts. The
specialist is the **marketer** resident session. Publishing is public and
irreversible — it is the most grant-guarded capability.

## Plan

- Fix the campaign frame: goal, account, platform, cadence, content
  scope, and what already exists (assets, drafts, brand voice).
- Consult the session early for strategy and critique ("この案の弱点は?",
  "このカレンダーは現実的?") — assessment turns need no Publish grant.
- Decide the Publish stance in the plan approval:
  - **Default: draft-only** (no `Publish:` line). The marketer prepares
    exact post text + attachments + destination; each post ships only
    after the user approves that exact content.
  - **`Publish: P1 @account, <=N posts, <scope>`** — autonomous posting
    within named caps, only when the user explicitly sanctioned it.

## Execute

Start the session with the SessionBrief (+ the Publish stance). Supervise:

- Copy production, thread structure, and scheduling proposals come back as
  turns; assets and long prose fan out to creator/writer sessions — you
  carry verified pieces between sessions.
- **Draft-only flow**: the session replies with the exact post
  text/attachments/destination → you relay it to the user **verbatim**
  (never paraphrase a post that is about to ship) → on approval, the next
  turn says "approved as-is, ship it" → the session posts via xurl and
  reports the live URL.
- **P1 flow**: the session posts within its caps and reports each live
  URL; you spot-check the first post immediately.
- Never approve a post autonomously, whatever the chat context; never
  widen caps mid-session without the user.

## QA

- Before relay/approval: copy matches the brief and brand voice; claims
  are true (check against sources); attached media passed
  `references/creative.md` QA; links resolve; platform constraints
  (length, media specs) hold.
- After posting: the reported URL is live and matches the approved
  content.

## Pitfalls

- Posting anything yourself, from any tool, ever — outbound publishing
  goes through marketer alone.
- Relaying a paraphrase of the post for approval instead of the verbatim
  text.
- Treating a P1 cap as renewable — expansion is the user's call.
- Letting an unverified asset or unchecked claim reach a post.
