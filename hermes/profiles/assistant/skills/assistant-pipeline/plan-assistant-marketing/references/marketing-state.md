# Marketing record pointer

Marketer owns the strategy record through marketer-pipeline references/state.md.
Give it the existing private project/job path when known; agree on one when
durable work needs it. Actual facts, accounts, drafts, approvals and reader
records stay outside both config repositories. Keep facts, hypotheses and user
decisions distinct; the fact ledger needs traceable sources, never plausible
filler.

Your own task records hold what you execute: released units, acceptance,
exact save consent and the saved draft's identity. When the work follows a
Marketer plan, pass the saved draft's identity and what the user later
published back to Marketer, so its record stays current. Reuse existing
positioning.md, offers.md, channels.md, facts.md, non-goals.md, decisions.md,
kpi.md and experiments.md without rewriting history or forcing a schema
conversion. Old Publish grants are historical, not authority for new work.
