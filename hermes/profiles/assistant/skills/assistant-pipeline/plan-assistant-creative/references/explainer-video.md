# Explainer video - make understanding possible

## Use

An explanation of a topic for an audience with a learning goal. A visible
software task is [tour.md](tour.md); a musical performance is
[music-video.md](music-video.md).

## Client decisions

Identify what viewers should understand or be able to judge afterwards,
their assumed knowledge and the source material supporting the explanation.
Keep simplifications and contested claims visible. Clarify whether a character
is wanted, existing or new when that is open; absence of a character file
does not mean "no character". Distinguish appearance from intended performance
and speech, without filling a producer form or promising automatic animation.
Note which script, identity, narration and facts already exist and
which need work for Execute, which releases each dependency as its own unit; do not duplicate
their requests or author a missing Writer script yourself.

## References

Use [reference research](reference-research.md) to compare how examples make
relationships or changes understandable. Do not prescribe a fixed opening,
diagram count, framing or teaching structure from a past production.

## Acceptance

Does the actual explanation meet the agreed learning goal without changing
approved claims or words? Are required character/performance/audio inputs
present, rather than silently downgraded? Keep factual grounding, visual
clarity and technical playback evidence separate; none proves the others.
