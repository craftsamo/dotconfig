# Writing — execute

The specialist is the **writer** resident session — it drafts; it never
publishes. Writing is **resident-only for now**: no `card_units`
(tone/structure feedback almost always arrives mid-flight; see
`../../plan/writing/index.md` for the revisit condition).

## Resident session

Start the session with the WritingBrief. Supervise:

- The deliverable is a file at a durable path (default `deliverable.md`
  under `~/Workspaces/.deliverables/<job>/`) plus a reply summarizing
  structure and choices.
- Feedback turns are itemized and quote-anchored ("リード文が硬い — 例:
  …", "第2章は結論を先に"). The session holds the draft; revisions are
  cheap.
- Text consumed by creator (scripts, captions) flows: writer turn → your
  QA → paste/attach into the creator session's brief (or the matching
  creator card's Inputs — e.g. a QA-passed final script feeding a
  `tts-voice` card).

## Pitfalls

- Publishing writer output anywhere — publishing is marketer's, behind a
  Publish approval.
- Briefing style mechanics the writer's own norms layers already own.
- Judging a draft by its summary, or forwarding unread text.
- Splitting one document across writer and your own inline edits — one
  owner per document; give feedback instead of patching.
