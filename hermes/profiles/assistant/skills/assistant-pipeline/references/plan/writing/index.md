# Writing — plan

Settle the WritingBrief before the session, from chat and memory:

- **Type** — copy / article / documentation / script.
- **Audience & purpose** — who reads it, what it must achieve.
- **Medium & tone** — where it appears; register (敬体/常体), voice, any
  tone samples you can paste.
- **Length / budget** and **language**.
- **Sources** — links, research conclusions (paste them — see
  `../research/index.md`), product facts.
- For production scripts: the artifact file name and the unit/field
  conventions the downstream producer expects (panels, cuts, timing).

The writer routes prose-vs-script and its Japanese norms layers itself —
brief the WHAT, not the style rules. Missing premises (tone samples,
target length) surface as one question round in its first reply; answer
or relay.

Writing is **resident-only for now** — no `card_units` are seeded,
because tone and structure feedback almost always arrives mid-flight.
Revisit only if a genuinely templated text class (fixed format, fixed
tone anchor, zero taste iteration) proves itself in resident use first.
