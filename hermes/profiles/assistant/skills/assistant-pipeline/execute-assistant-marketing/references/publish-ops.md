# Service drafts

Every marketing save ends at an unpublished draft on the service, saved by
you and reopened. The route-specific mechanics live in each technic or tool
reference; these rules hold across them.

## Consent and record

- Approval binds the exact text and assets, the named service and account,
  and create versus update of a named draft. For an update it also binds the
  current remote content you read: if that changed since the user approved,
  read it again and ask anew. Never overwrite a human edit.
- Record in the task record, before editor entry: the input version or hashes,
  the target, the approving user message (not your own summary of it) and the
  route. Record the draft's identity as soon as the service assigns one.
- A tool with an approval card (`note`, `substack`) makes the card the final
  remote-save consent; still agree the full text first, since the card shows
  only its start.

## Boundaries

- No publication, scheduling, send/test-send, audience or visibility change,
  Publication association or sharing/preview link, even where a tool offers
  it. Published or scheduled targets are out of scope.
- Use your own authenticated browser profile only; never Marketer's or a new
  one. Authentication challenges go to the user.
- Wording changes go back to Writer; a markup-only representation fix may
  change markup, never meaning, wording, URLs or qualifications.

## Verification

Reopen the same object through the service's draft management or the tool's
read, compare title, body, links, code, images and their order with the
approved version, and confirm unpublished status from an actual status
surface. Report `draft-created`, `draft-updated`, `save-uncertain` or
`blocked`; a saved badge, typed-text screenshot, guessed URL or HTTP success
alone is not a verified save.

## Uncertainty and incidents

On an interruption or timeout, look for the known draft before anything else;
never create a second draft to recover and never delete one as cleanup. Report
`save-uncertain` with what you know. An unexpected publication, send or other
public effect is an incident: stop, report the known URL and effects, keep the
evidence and let the user decide.

Old P0/P1 jobs/grants and old Marketer draft records are not silently adopted;
reconcile and release new draft-only work. Historical posts/records stay
unchanged. See [Execute](../SKILL.md).
