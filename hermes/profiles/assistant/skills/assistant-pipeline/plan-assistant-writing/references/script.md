# Script — decision surface

Producer-facing narration, comic scripts, storyboards, screenplays and slide
scripts. The audience determines content; the actual consumer determines text
representation. A script is not a rendered or synthesized artifact and does not
by itself prove that a particular production tool can execute the instructions.

Writer type `script` · QA `script` · units: outline, piece or whole small job.
Select `write-script` for new production text, `edit-script` for named changes
to an existing script, and `analyze-script` for observations about a target.
The analysis report has its own branch in the script QA contract; it is not a
new script. Pre-draft advice without a target remains planning consultation.

## Fix before release

- **Audience and purpose** — the intended listener/viewer and what the piece
  conveys or enacts. Do not force a hook, CTA or story arc when not requested.
- **Format and consumer** — narration, comic, storyboard, screenplay,
  slide-script or a described custom format. Supply the actual producer_format
  when its fields, unit IDs or input files determine usability. Plain narration
  needs no scene table; a slide outline without spoken production text is Document.
- **Story and evidence** — source_story/approved outline and constraints. Identify
  fictional freedom versus factual narration, quotations and claims needing sources.
- **Speakers** — relevant identities, attribution and writing voices. These are
  not voice-engine controls or permission to create a registered voice.
- **Quantities** — required counts, text bounds and duration targets with units.
  Distinguish target from hard limit and intended timing from measured playback.
  Unknown required evidence remains a dependency, never an invented count or fit.
- **Artifact representation** — identify master, verbatim fields, required raw
  speech files and separate production notes. The file consumed as speech must
  contain only intended words, not labels, fences or staging instructions.
- **Edit/analysis scope** — original, changed units/protected content, or the
  question and comparison source. Bounded analysis needs only relevant criteria.
  Humanizer is explicit-request only and cannot authorize rewriting an analysis.

## Release and acceptance

Multi-part work uses an outline release and approved pieces as needed. A short
whole narration does not require an extra approval ceremony before writing.
Respect existing unit IDs; mark retired IDs in the structure/notes without
reusing or speaking them. Requested re-identification requires an explicit
old-to-new mapping agreed with the requester and consumer.

The requester independently accepts the actual words/fields before releasing
production. A changed script needs renewed approval and dependent timing/media
re-verification. Existing audio evidence does not become evidence for new words.
Use the consumer's actual limits; if sectioning is necessary, agree on it before
new work is released. Do not grant extra takes or silently truncate a script.

## Red flags

- Unknown required consumer fields or unsupported production requirements hidden
  by a plausible storyboard. Return the specific gap, not a generic render promise.
- A formatted master or analysis report passed as a raw speech input.
- Character count presented as proof of precise audio duration or subtitle sync.
- Writing and dependent production released together before text acceptance.
