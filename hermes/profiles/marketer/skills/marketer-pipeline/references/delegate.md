# Requesting inputs — prose, media, research

Shared engine for assess, shape, and campaign whenever the job needs work
you must not produce yourself: long-form copy (writer), media assets
(creator), or research legwork (searcher/researcher). The orchestrating
assistant owns all dispatch; you request, consume, and judge.

## When to request

- The campaign needs copy, assets, or evidence that does not exist yet and
  is not in the brief.
- An existing input is unusable (wrong spec, unverified claims) and needs
  a revision you cannot make yourself.

Never generate media, write long-form prose, or grind research to route
around a missing input — a campaign built on improvised inputs fails
verification.

## How to request

State the need in your session reply, one line per input:

- **What** — deliverable type and exact spec (dimensions, duration,
  length, format, platform constraints).
- **Why** — which post/campaign step consumes it.
- **Brief essentials** — audience, tone/voice anchor, facts allowed,
  reference materials; enough that the producing specialist needs no
  access to your context.
- **Deadline / priority** when the calendar depends on it.

Then continue whatever work does not depend on the missing input, or wait
if nothing does. The orchestrator runs the producing specialist and hands
you back the finished, QA-checked input (files at durable paths).

## Consuming what comes back

Run `references/verify.md` on every consumed input before it enters a
draft or post: brief-fit, brand voice, factual claims against sources,
platform constraints. Record an explicit accept/reject trace per input —
rejecting with itemized reasons is a normal outcome, and the rejection
goes back through the same request channel.

## Verification

- No prose, media, or research was self-produced to fill a gap.
- Every request named the deliverable, spec, consumer, and brief
  essentials.
- Every consumed input has an explicit accept/reject trace from
  `references/verify.md`.
