# Collect observations

Start with the question and the named account/content/period, not every metric
an interface exposes. Resolve permission to inspect authenticated information;
general marketing advice is not permission to browse all logged-in accounts.
Use [draft's browser lease](draft.md) for all authenticated navigation and leave
open editing surfaces alone. Do not change settings, export/sharing permissions
or start a recurring collector as part of reading results.

Choose an available source: permitted public observation/search, the existing
account's dashboard, an already-authorized integration, or a user-supplied
export. Read the selected platform reference. If a dashboard or metric is
unavailable, report that; do not silently install a tool, buy access or fabricate
clicks, unique readers, retention or attribution from visible reactions.

For each observation retain source/locator, account/content identity, retrieval
time, period/time zone, metric definition, value/unit and relevant denominator.
Keep native counts separate from derived calculations. Distinguish:

- measured zero;
- not measured or not exposed by the service;
- retrieval failed;
- observed but not comparable with the requested period/definition.

Check identities and duplicates before aggregating. Do not add subscriber counts
across services and call them unique people. Email opens can be distorted by
privacy/proxy behavior; a click is not a purchase, and no visible reply is not
proof nobody read. Preserve these limits in the record.

Minimize personal data. Prefer counts and necessary redacted excerpts; do not
send private reader/customer records to research peers or external analysis
services without scoped consent. Record in [state](../state.md), release the
lease once navigation is safely complete, and pass observations to
[Analyze](../analyze/index.md). Collection itself makes no success verdict.
