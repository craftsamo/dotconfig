# Verify the saved service draft

Keep the browser lease from [Build](../build/draft.md) until verification or a
reconciled stop. Read the selected platform's identity/persistence limitations.

Reopen the same object through the service's draft management surface or a
confirmed private editor locator. Confirm the correct account/publication and
content type. A local manuscript, input screenshot, save badge, guessed public
URL or browser-history entry alone does not establish service-side persistence.
An article's author name is not proof of the currently authenticated account;
use an account-specific UI indicator or report that identity as unverified.

Compare title, complete body and relevant structure against the approved inputs.
Check links, code, quotations, qualifications, images and their order/placement.
Markup differences are acceptable only if the approved meaning and required
rendering survive. Inspect actual preview/rendered output without generating a
share link or widening visibility. Never claim uninspected long content passed.

Confirm draft/unpublished status, no scheduled publication, no unintended email
or test send, and no new sharing scope or organization/publication assignment.
Do not infer unpublished status from an editor's Publish/Continue button alone;
require an actual status surface such as the authenticated unpublished banner.
If status is ambiguous, stop and report unverified; do not probe a publish button.
Distinguish evidence that settings remain safe from proof about unobservable
notifications; do not claim a send audit the service does not expose.

Report one of: `draft-created`, `draft-updated`, `draft-verified`, `save-uncertain`, `blocked`.
The first two require reopened content and unpublished-state evidence. Record
the private editor locator/identity, account, input version, timestamp, checks
and any explicit limitations in [state](../state.md). A shared/secret preview
link is not a private editor URL. Do not generate one as a delivery convenience.

For an explicitly read-only recheck of an existing draft, use `draft-verified`
only for the requested, actually inspected scope; never claim a new save/update.
Name controls or settings outside that scope as not inspected rather than
certifying them from the banner. A full save's required safety checks are not
waived by this narrower report. If any requirement of the released recheck is
unverified, report that requirement as unverified, not a completed verification.

Changed wording returns through Writer and renewed acceptance/remote-save
approval. A save is not rolled back by silently deleting it. After verified
completion or a reconciled stop release the current owner's lease and report.
