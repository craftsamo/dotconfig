<Procedure>

1. Work only in `specialist_call(kind="work")`: rendering and verification are
   several files and commands. Read the form. `what_for`, `motion` and `grid`
   are required, and so is `subject` when there is no `source`; a missing one
   is a single `Q1:` block. Defaults: `effective_fps` 10, `loop` yes, `scale`
   8, `gif` no. The container fps is the smallest integer multiple of
   `effective_fps` that is at least 24 (10 gives 30, 12 gives 24), so every
   native frame is held an equal number of container frames.
2. Lock one motion statement and the protected static regions in `qa.md`
   before drawing: what changes, what stays identical in every frame, and why.
   A character or story action needs a cel plan (one line per frame) first.
   A `source` directory or `palette.json` fixes the palette exactly; a lone
   native PNG fixes it from its opaque colours.
3. Draw native-grid cels as `maps/frame_0001.json`, `frame_0002.json`, … under
   `deliver`, each `{"palette": {"a": "#rrggbb"}, "rows": ["..aa..", ...]}`
   (`.` is the background), every map with the same palette and size. When
   a `source` exists, redraw or re-threshold the cells of each frame from it:
   never rotate, sub-pixel translate, blur or interpolate a finished bitmap.
   Camera movement and parallax shift whole cells by integer steps only.
   Build a true cycle: the last frame is not a copy of the first; the
   last-to-first step is just another step. Render, in a command of its own,
   with an `--out` that does not exist yet:

   ```
   uv run --no-project --with Pillow python ${HERMES_SKILL_DIR}/scripts/cels.py draw \
     --maps <deliver>/maps --out <deliver>/frames [--background <#rrggbb>]
   ```

   It refuses a mixed palette or size and prints one `RESULT:` line. Then
   build the contact sheet, again in a command of its own:

   ```
   uv run --no-project --with Pillow python ${HERMES_SKILL_DIR}/scripts/cels.py sheet \
     --frames <deliver>/frames --out <deliver>/sheet.png --scale 4
   ```

4. Encode, in a command of its own with `background: true`, and poll:

   ```
   ${HERMES_SKILL_DIR}/scripts/encode-pixel-video.sh '<deliver>/frames/frame_%04d.png' <deliver>/pixel_<slug>_master.mp4 \
     --scale <N> --effective-fps <F> --container-fps <C> --compat <deliver>/pixel_<slug>.mp4 [--gif <deliver>/pixel_<slug>.gif]
   ```

   It scales by nearest neighbour only, writes an RGB-lossless `libx264rgb`
   master and a yuv420p compatibility copy (an odd `scale` is refused). A
   successful ffmpeg exit is not acceptance evidence.
5. Verify both files with the ported verifier, each in a command of its own,
   with every contract value. `--palette-max` is the number of colours in the
   locked palette plus the background; `--loop` or `--no-loop` follows the
   form. Save each printed output; `verify.json` records the two commands, the
   exit codes and the output lines:

   ```
   uv run --no-project --with Pillow --with numpy python ${HERMES_SKILL_DIR}/scripts/verify-pixel-video.py \
     <deliver>/pixel_<slug>_master.mp4 --master --grid <WxH> --scale <N> --palette-max <K> \
     --effective-fps <F> --container-fps <C> --loop --source-pattern '<deliver>/frames/frame_*.png'
   uv run --no-project --with Pillow --with numpy python ${HERMES_SKILL_DIR}/scripts/verify-pixel-video.py \
     <deliver>/pixel_<slug>.mp4 --compat --grid <WxH> --scale <N> --palette-max <K> \
     --effective-fps <F> --container-fps <C> --loop
   ```

   Both end with a `PASS` line; a `FAIL` line is fixed by redrawing into a new
   `frames` directory, never by relaxing a contract value.
6. Vision: look at `sheet.png` first, then at two or three native frames
   (the first, a mid-cycle frame, the last) from the master. Check the
   protected regions are identical and the requested parts move. Append each
   look's finding to `qa.md` before the next look; `qa.md` is appended, never
   rewritten.
7. `intent: revise` — read the previous delivery's `maps/` and palette, apply
   only the change, and rerun from step 3 into new directories.

Execution traps: every `uv run`, `magick` and encode call is a command of its
own (the write guard reads the whole command, so no `cp … &&` before it);
quote the `%04d` and `*` patterns; non-ASCII text goes through files, never an
argv string; `uv`, `magick`, `ffmpeg` and `ffprobe` must be on `PATH`, or the
script stops with `'<tool>' not found`; the master is verified as a file, so
never re-encode it through yuv420p to open it.

</Procedure>

<QA>

Every check with its evidence:

- **Grid and scale** — output size is exactly `grid` times `scale`; nonuniform
  blocks 0. Verifier-checked.
- **Palette** — the union across all decoded frames stays within the locked
  palette (`palette:` line); no interpolated colour. Verifier-checked.
- **Cadence** — native changes per second match `effective_fps` and every hold
  equals container over effective fps (`cadence:` line); container fps as set.
- **Loop seam** — for `loop: yes`, the wrap difference is within the normal
  step range (`loop:` line); the last frame is not a duplicate of the first.
- **Master identity** — the master equals the native source frames
  (`source identity: N/N exact`), is planar full-range RGB and stays the
  lossless master; the yuv420p copy is labelled as compatibility only.
- **Protected regions and motion** — protected regions are invariant and the
  requested parts move, from the verifier's motion count plus vision on the
  sheet and sampled frames.

A failed check is a fix within the leaf; one that cannot be fixed (a grid too
small for the motion) is reported as a gap, never delivered as passed.

</QA>
