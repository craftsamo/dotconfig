# Image craft reading

This kernel reference covers all existing image leaves, not a new form or style
catalog. Before a creative choice, read `skill_view(name="media-craft-visual")`
and only the applicable files below, using that skill's `file_path` argument.
Existing leaf/style references still own actual tools, controls and constraints.

| Subject and decision | Visual reference files |
| --- | --- |
| card layout and exact-copy treatment | `references/composition.md`, `references/typography.md`; `references/surface-light.md` only when material/light is a real choice |
| icon optical weight or silhouette | `references/symbols-characters.md`; `references/systems-assets.md` for sets |
| emoji expression and small-size identity | `references/symbols-characters.md` |
| mascot pose, gesture and identity | `references/symbols-characters.md`; `references/surface-light.md` for modeled/painted form |
| reimagine medium and protected subject traits | `references/generation.md`; `references/surface-light.md` when applicable |
| kit component relationships, states and geometry | `references/systems-assets.md`; `references/symbols-characters.md` for icon sets |

For any `generate` operation, also read `references/generation.md` before the
prompt decision. For source selection, read only when judging fit or consistency;
an exact named-asset fetch does not need a redesign. An edit/analyze operation
reads the reference for the requested visual judgment, not the entire table.
Pure size/format/byte-cap changes and accepted frozen-output packaging skip craft.

When the issue is the chosen effect itself rather than execution, additionally
read `skill_view(name="media-craft-direction")` and its
`references/critique-revision.md` (or `references/reference-interpretation.md` for
a supplied analogy). Return a changed creative direction to Creator; reading a
skill does not authorize it. Preserve exact words, identity and actual immutable
pixels; distinguish those scopes rather than guessing which may change.

Required craft bodies must be in current context before the affected decision.
If a lookup is unchanged but the body is missing, recover the canonical file
under `~/.agents/skills/<skill>/` with `read_file`, following genuine truncation.
An unavailable or ambiguous required resource stops that creative action with
its exact name; do not install, list the whole store or quietly choose a weaker
substitute. Unrelated mechanical work and optional-reference policies are unchanged.

Use the existing `qa.md` for the resources read, the decision they informed and
the actual native/use-size evidence. Skill availability is not evidence of use;
described examples are not rendered proof. Honor the leaf's bounded look/revision
budget and all proposal, generation, upload and final-approval gates.
