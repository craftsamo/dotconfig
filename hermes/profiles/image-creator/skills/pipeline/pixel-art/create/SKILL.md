<Procedure>

1. Read the form. `what_for`, `mode` and `grid` are required, and so is
   `source` when `mode` is `reduce` and `subject` when it is `draw`; a
   missing one is a single `Q1:` block. `background` defaults to
   transparent, `preview_scale` to 16. A thin logo, glyph or diagonal needs a
   grid that can carry it: if the form does not settle that, ask, never
   discover it at review.
2. Pick the palette. A named palette goes to the backend by its upper-case
   name (`PICO_8`, `GAMEBOY_ORIGINAL`, `NES`). A colour cap or `from:` goes
   through `scripts/palette-extract.py apply` (sample = the source for a cap;
   for `from:`, the native PNG delivered beside that `palette.json`). No
   palette means the backend's `arcade` preset. A batch with `from:` applies
   that palette exactly; never quantize each item on its own.
3. Produce the native PNG under `deliver`. Never rotate or resample a
   finished bitmap.
   - `reduce`: run the render script in a command of its own, with
     `background: true` if it may take long, and poll:

     ```
     ${HERMES_SKILL_DIR}/scripts/render-pixel-art.sh <source> <deliver>/pixel_<slug>.png <deliver>/pixel_<slug>_x<N>.png \
       --grid <WxH> --preset arcade [--palette <NAME>] --preview-scale <N> \
       --fit <cover|contain> --gravity <gravity> --background <none|#rrggbb> --alpha <preserve|flatten|reject>
     ```

     State `--fit`, `--gravity` and `--alpha` explicitly from the form (a
     transparent `background` is `--alpha preserve`, `--background none`; a
     colour is `--alpha flatten` with that colour); never accept a default
     the form contradicts. It finds the `pixel_art.py` backend under
     `~/.agents/skills/pixel-art` or the hermes-agent optional-skills
     checkout; record the printed `backend:` path in `qa.md`. Then write
     `palette.json` with `pixel.py palette`.
   - `draw`: write `map.json` under `deliver` from `subject`, as
     `{"palette": {"a": "#rrggbb"}, "rows": ["..aa..", "..aa.."]}` with `.`
     for a transparent cell, every row of the grid width and the grid's row
     count; with `from:` use exactly that palette's colours. Render it, in a
     command of its own, with a `--out` that does not exist yet:

     ```
     uv run --no-project --with Pillow python ${HERMES_SKILL_DIR}/scripts/pixel.py draw \
       --map <deliver>/map.json --out <deliver>/render --scale <N> [--background <#rrggbb>]
     ```

     then copy `render/native.png` to `pixel_<slug>.png`, `render/preview.png`
     to `pixel_<slug>_x<N>.png` and `render/palette.json` to `palette.json`
     (one copy per command).
4. Check, in a command of its own (writes nothing):

   ```
   uv run --no-project --with Pillow python ${HERMES_SKILL_DIR}/scripts/pixel.py check \
     --native <deliver>/pixel_<slug>.png --preview <deliver>/pixel_<slug>_x<N>.png \
     --palette <deliver>/palette.json --scale <N> --alpha <transparent|opaque> [--max-colors <cap>]
   ```

   It prints one `RESULT:` line and exits non-zero on a failure; fix and
   rerun with a new `--out` (draw) or new output names (reduce).
5. Vision: join the native (shown at the preview size) and the preview into
   `sheet.png` with `magick … +append`, never `montage` (no default font
   here); look at `sheet.png` first, then the preview. Append each look's
   finding to `qa.md` before the next look; `qa.md` is appended, never
   rewritten.
6. `intent: revise` — read the previous delivery's `palette.json` (and
   `map.json` for `draw`), keep the palette, apply only the change, and rerun
   from step 3.

Execution traps: every `uv run` and `magick` call is a command of its own (the
write guard reads the whole command, so no `cp … &&` before it); Japanese and
other non-ASCII text goes through files, never an argv string; `uv` and
`magick` must be on `PATH`, or the script stops with `'uv' not found`.

</Procedure>

<QA>

Every check with its evidence:

- **Files** — native PNG, preview PNG, `palette.json`, `sheet.png` and
  `qa.md` exist.
- **Grid** — native size equals `grid` (`native=` in the `RESULT:` line).
- **Palette** — colours are within the locked palette (`out_of_palette=0`),
  no partial alpha, and for a colour cap the count stays within it; no
  intermediate anti-aliased colours. Script-checked.
- **Preview** — an exact integer multiple of the native size with uniform
  blocks (`uniform_blocks=yes`). Script-checked.
- **Transparency** — as asked (`alpha=` in the `RESULT:` line).
- **Vision** — silhouette and features legible at native and preview size;
  for `reduce`, protected source features (face, glyph, outline) kept.

A failed check is a fix within the leaf; one that cannot be fixed (a grid
too small for the source) is reported as a gap, never delivered as passed.

</QA>

`RESULT:` line; each QA check with its evidence; `spend: free`; anything the
