<Procedure>

1. Read the form. `what_for`, `kind` and `content` are required; a missing
   one is a single `Q1:` block. A label the form leaves out is never
   invented: ask for it. `size` defaults to 1600x900, `theme` to light.
2. Load the drawing engine, for its drawing conventions only (never its
   clarify or intake): `skill_view(name="architecture-diagram")` for
   `architecture`, `skill_view(name="concept-diagrams")` for `flow`,
   `sequence` and `concept`. An unlisted `kind` uses the closest engine.
3. Write under `deliver`, from the form, never from memory:
   - `labels.json` — a JSON array of every label string, verbatim.
   - `diagram_<slug>.html` — one self-contained HTML file with inline SVG
     sized to `size`: no `<script>`, no remote URL, no linked stylesheet,
     fonts by system family names only. Every label is SVG `<text>` content,
     one label per `<text>` or `<tspan>`.
   Japanese and other non-ASCII text goes through files, never an argv
   string (the terminal guard refuses `。` in a command).
4. Render. Run the script in a command of its own (the write guard reads the
   whole command, so no `cp … &&` before it), with `background: true` if it
   may take long, and poll:

   ```
   ${HERMES_SKILL_DIR}/scripts/diagram.py render --html <deliver>/diagram_<slug>.html \
     --labels <deliver>/labels.json --size <WxH> --out <deliver>/render
   ```

   `--out` must not exist. The script checks the HTML is self-contained and
   that every label occurs in the SVG text, renders offline at 1x and 2x,
   requires two identical screenshots and no browser errors, and prints one
   `RESULT:` line. On a failed check fix the HTML and rerun with a new `--out`.
   Then copy `diagram.png` to `diagram_<slug>.png` and `diagram@2x.png` to
   `diagram_<slug>@2x.png` in `deliver` (one copy per command).
5. Vision: look at `render/sheet.png` first, then `diagram_<slug>.png` at 1x.
   Append each look's finding to `qa.md` before the next look; `qa.md` is
   appended, never rewritten. Join images with `magick … +append`, never
   `montage` (no default font here).
6. `intent: revise` — read the previous delivery's `labels.json` and HTML,
   apply only the changed content, and rerun from step 3.

</Procedure>

<QA>

Every check with its evidence:

- **Files** — `diagram_<slug>.html`, the 1x and 2x PNGs, `sheet.png`,
  `labels.json` and `qa.md` exist; measured sizes from the `RESULT:` line:
  the 1x PNG equals `size`, the 2x PNG is twice it.
- **Labels exact** — the script's check: every string in `labels.json`
  appears in the SVG text of the HTML (`labels_ok` in `render.json`).
- **Self-contained** — the script's check: no remote reference, no script,
  no stylesheet link (`self_contained` in `render.json`).
- **Stable render** — two identical screenshots and no browser errors
  (`stable`, `errors` in `render.json`).
- **Vision** — on the sheet and the 1x PNG: no overlapping labels, no
  clipped text, no hidden or crossing-ambiguous connectors, legible at the
  1x size.

A failed check is a fix within the leaf (edit the HTML, rerun); one that
cannot be fixed is reported as a gap, never delivered as passed.

</QA>

with its evidence; `spend: free`; anything the Assistant must decide (a
