# Build — image-creator: card

Read [common build](../../SKILL.md) first.

## Transport

| Leaf | Transport |
| --- | --- |
| image-creator's generate-card, authored-layout/custom-style Card or multi-tile Card | `kind="work"`; explicit budget/creative questions or multiple local renders/looks need the same persistent conversation |

`create-card`, `edit-card` and `analyze-card` are free, bounded one-reply
leaves: use the generic `inquiry` row in [common build](../../SKILL.md) instead,
but only for a simple, single-tile, named-style template case. An authored-layout,
custom-style or multi-tile request on any of these leaves still takes the `kind="work"`
row above, the same as generate-card.

## Supervising

Card uses create/generate/edit/analyze-card before the retained legacy mapping.
Pass the literal form, ordered tile_titles/files and all destination caveats.
Generate-card cannot spend from a generic default: relay explicit current-work
user approval and preserve its attempts.json tally across resumes, including
failures. Inspect backend aspect/ref-input preflight before release. Local
typesetting of existing art is free; do not buy new art for a text-wrap defect.
Let ImageCreator choose template versus authored source by actual requirements,
including for a named look. Revisions preserve approved copy/placement and use
the editable source as evidence. A failed template does not authorize a changed
brief, extra generation, silent legacy fallback or an Assistant decision being
relabeled as human approval. Existing proposal/preview and budget gates remain.
The task directory may exist, but each render bundle below it must be new;
do not pre-create its exclusive output path. Analyze needs only retained
measurement/report text when requested, never a corrected card. No new
profile/toolset or authenticated browser is needed to render a card.
