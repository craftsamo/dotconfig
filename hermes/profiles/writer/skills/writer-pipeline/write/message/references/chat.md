# Chat reply

Use only the supplied relevant exchange and the sender's intended response.
Resolve what a pronoun or shorthand refers to when the context supports it;
otherwise ask instead of assigning a meaning. A short answer need not become
an essay, and a long answer need not be split into an unsolicited sequence.

Keep the reply's purpose visible. Match the requested language and distance
without inventing emotions, agreement, availability or a reason for delay.
Do not infer a personal relationship from a handle or consult contact records.
Mentions or links must refer to supplied destinations, not guessed accounts.

For custom chat syntax use the provided channel rules or plain text. Do not
assume Markdown will render, or use invisible HTML comments for review notes.

## Craft decisions

Build one contextual unit the recipient can understand and, if requested, act
on: name the topic, give the answer, then the specific request if there is one.
If several previous referents make 「それ」 ambiguous, name the supported one.
Do not repeat a noun merely to lengthen an already clear adjacent reply.
Keep short informative replies short; no greeting or demand is required.
If there are independent tasks, separate them only within the released scope;
do not scatter a condition and its action across disconnected messages.

## Worked example

Fictional material: colleagues discussed both a venue and a meeting time.
The sender has decided on the venue only: 第2会議室. The purpose is to tell
the colleague that decision in one sentence; no action or time is supplied.
Draft: 「会場は第2会議室に決まりました。」
Why: naming the venue resolves which topic was decided, while the short
sentence conveys the complete update without inventing a meeting time.
The decision is informative; a command would add work the sender never asked for.

Retain: if the immediately preceding question names one venue, an unambiguous
short answer can stay short rather than repeating the whole exchange.
Counterexample: 「それでお願いします。予約もお願いします。」 leaves the
referent unclear and adds an unauthorized reservation request in this example.

QA evidence: pair the reply's named topic with the relevant supplied turn and
compare any action with the sender's request. State missing context when two
readings remain possible; do not claim to know the recipient's reaction.
