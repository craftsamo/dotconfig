# QA contract — script

Inspect the actual artifact from the released request, not just the receipt.
Choose the draft or analysis branch by operation. The format does not make an
analysis report a new script requiring its own dialogue or production fields.

## Script draft (write-script / edit-script)

Read the complete released outline/piece/script, the brief, relevant evidence
and any required production notes/raw exports. For an edit also compare the
original and named changes. Check the actual consumer representation; do not
assume every media tool can consume a multi-unit storyboard.

- Match audience, purpose, approved story scope, speaker roster and relevant
  producer fields. Plain narration needs no scene table or compulsory CTA.
  An outline is judged as an outline, not a missing final manuscript.
- Preserve stable unit IDs, explicit order and references. Removed units retain
  retired IDs outside verbatim text; do not compact/reuse them. Re-identification
  requires an approved old-to-new mapping accepted by requester and consumer.
- Verify exact spoken/displayed words are distinct from action, timing,
  pronunciation and staging instructions. A raw speech file contains words only:
  no headings, speaker labels, fences, QA notes or retirement markers. Check
  required exports and unit/speaker mappings against the master. Production
  notes are not a speech input, and a stale export is not the revised script.
- Compare facts, quotes, qualifications and permitted fiction with the sources
  and approved story. A tone change does not authorize new facts or identities.
  Review neighboring units and untouched fields for continuity after edits.
- Check actual text limits with a reliable method. Duration targets and reading
  estimates are not measured playback, synchronization, acting, pronunciation
  or rendered lettering fit. Old timing/media evidence may not cover revised
  words; missing required evidence is NOT verified, not a manufactured pass.

Return defects to the same Writer session without rewriting dialogue, renumbering
units, extracting/replacing approved raw text yourself, or producing media.
Changed scripts need renewed acceptance/approval before dependent production.
Writing acceptance is not synthesis, rendering or an extra take grant.

### Script scoring anchors

Apply [Writing QA](index.md#evidence-anchored-scoring) to the released text
scope. Use the actual producer's contract, not genre-wide counts or invented
timing limits. An outline needs a coherent sequence, not finished dialogue.

| Format | Evidence of usable craft (3 or 4) | Defect requiring correction (2 or below when in scope) |
| --- | --- | --- |
| Narration | Spoken order establishes referents before depending on them and preserves essential qualifications without dense nesting. | "Choose this" depends on an unseen selector or a simplification drops a critical condition. |
| Comic | Supplied panels, speakers, visible beats and words have complementary roles; stable IDs remain usable. | An essential story beat disappears between panels or dialogue is assigned to the wrong speaker. |
| Storyboard | Each supplied unit's visual, words and transition convey the intended progression and map to production fields. | A transition contradicts the preceding state or unapproved units/IDs replace the supplied sequence. |
| Screenplay | Observable action and permitted dialogue express the agreed scene and supplied character voice. | Exposition changes a protected motive or an unobservable narrator comment replaces a needed filmable action. |
| Slide-script | Spoken explanation supplies the essential relationship in a chart/slide without merely reading every label. | Meaning depends solely on "as you can see here" or the words contradict the visible message. |

Fictional calibration: producer supplies a Save button that starts saving, not
confirmation of completion. "Select Save to start saving" respects that state;
"Your work is now saved" invents completion. Separately, dialogue and events
invented within an approved fictional scene are not fabricated factual evidence.
Reading a script supports a textual speakability judgment, never a claim of
measured duration, actual pronunciation, acting or synchronization. No audio
generation or extra performance test is added by the score itself.

## Script analysis (analyze-script)

Read the actual report, target and comparison material when applicable. A
permitted short report is read in full in the reply. Check that observations
answer the question, cite the relevant unit/field/words, and distinguish
interpretation from textual facts and unknowns. Comparisons read both inputs;
descriptions need not invent faults or a winner.

Producer-fit claims need the actual contract and inspected representations.
Timing claims need evidence for the specific version and conditions. Do not
infer a rendered result, voice performance or a supported production route from
text alone. Missing context limits the conclusion, not every bounded observation.

This report needs no new scenes, dialogue, speaker roster, narration export or
production-ready fields. It is not a production part and cannot authorize a
rewrite, ID change, audio take, timing-file update or publication.

Score the report using [Writing QA](index.md#evidence-anchored-scoring).
It may identify an ambiguous spoken referent by quoting the unit and its visual
dependency without generating replacement narration. A precise reading-time
claim without version-matched measurements needs correction; "duration is not
verified" may be a valid answer to the available scope, not a defect in the
analysis itself. Do not deduct because the target script has real problems
that the report correctly identifies.

## Evidence and limits

Use checked / unmet / unverified evidence for applicable criteria and inspect
the actual artifacts independently. No legacy lint, four-pass receipt or
automatic humanizer applies; humanizer is explicit-request only and never
permission to repair during acceptance. Unavailable required evidence stays
NOT verified. Do not research new facts, render, synthesize or publish in QA.
