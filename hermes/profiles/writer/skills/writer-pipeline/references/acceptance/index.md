# Writer acceptance — the requester's gate

Read the actual file, whole — never judge from the reply summary.
All six writing families use their own leaf QA and the gates below, on top
of the common floor immediately below. Your acceptance always checks actual
evidence, not a claimed pass count.

## Common floor (every acceptance)

- **Inspect the actual artifact** at its durable path, never Writer's
  description of it or a reply summary.
- **Judge against the brief**: the settled done criteria and applicable
  conventions — not personal taste. Taste calls belong to the requester;
  contract violations belong to feedback.
- **Findings are itemized evidence**: what was checked, the quoted passage
  or section/unit reference, and the defect or the pass. An unnamed check
  did not happen.
- **External facts need evidence**: claims, citations, numbers and quotes
  resolve to the supplied sources; acceptance checks the text represents
  that evidence accurately, it does not re-research.
- **Never repair**: no editing, rewriting or regenerating during
  acceptance. Defects go back to the same Writer session.
- **Cannot verify ≠ pass**: an unreadable file, missing evidence, or an
  unknown family/operation means NOT verified — obtain what is missing or
  say plainly it cannot be checked; never accept on resemblance.

Planning-only consultation is decision input, not an artifact release or a
writing-QA pass. Read its full reply and resolve open decisions before releasing
writing. It needs no manuscript path and must not be forwarded as approved text.
An explicitly released outline is an artifact and still uses the outline gate.

## Served post gate

Select from the released request, not solely the Writer's reported name:
`write-post` and `edit-post` use the post-draft branch of `prose.md`;
`analyze-post` uses its analysis-report branch. An analysis is not a post
and must not be rejected for missing publishable bodies or attachments.
Read a permitted short analysis in full in the reply; it does not exempt
actual draft units from durable file delivery.

Require the selected leaf, actual output, source/brief, and applicable
criterion evidence as checked / unmet / unverified. For an edit also read
the original; for an analysis read its target and comparison source when
applicable. Inspect the actual text, claims, protected wording and media
mapping. Defects return to the same Writer session, and unavailable evidence
is NOT verified. Writer self-review does not replace your independent check.

Do not run legacy Japanese inspection scripts, require four named passes,
or load humanizer automatically for these units. Humanizer is used only if
the released request explicitly asked for it, and never to repair during QA.
No separate legacy writing gate follows these checks.

## Served article gate

From the released request, select `write-article` / `edit-article` for an
article draft or `analyze-article` for an analysis report. Use the matching
article branch in `prose.md`; do not require four legacy passes, legacy
lint or automatic humanizer. Analysis is judged as a report, not a new
article needing media. Read a permitted short report in full in the reply.

For an outline, check the agreed purpose, structure and tone, then wait for
approval rather than demanding full prose. For a draft, read the entire file
and any same-stem `.production.md`; check sources, protected content and
the selected destination representation. For an edit, compare the original
and authorized scope. Marker IDs must match actual supplied assets or explicit
missing requirements. Text-only acceptance is not asset/editor completion or
publication readiness. Missing requirements inside the released unit are
NOT verified and return to Writer or the responsible producer.

For article edits within a proofread or wording scope, and for analyses, the
article branch is the applicable gate; the generic new-writing outline/full
gate below does not add reader, tone, research or publication requirements.
Proofreading acceptance confirms the correction scope and preservation of the
source, not all factual claims.
Keep reported factual doubts or missing unrelated media separate from completion
of that narrow unit; never hide them or call the article publication-ready.
Explicitly requested factual checks still require evidence and acceptance.
Structure/rewrite units retain their applicable full gate, including source
trace for claims; the narrow-correction exception does not apply to them.

## Served document gate

Select from the released request, not only the receipt: `write-document` and
`edit-document` use the document-draft branch in `prose.md`; `analyze-document`
uses its document-analysis branch. Read a permitted short analysis in full
in the reply. Analysis is a report, not a new document needing its target's
template, owners, deadlines or operational results.

For a draft/outline, inspect the complete released artifact, format, scope,
brief and supplied sources. For edits also compare the original and named
changes; for comparisons read both sources. Check only relevant format
requirements and protected content. Missing from the record is not an explicit
decision; a plausible command is not a verified run, and a slide outline is
not a rendered deck. Unavailable required evidence remains NOT verified.

Use checked / unmet / unverified criterion evidence and independent reading,
not legacy lint, four-pass counts or automatic humanizer. Humanizer is
explicit-request only and never permission to repair during acceptance.
Defects return to the same Writer session; the consumer does not rewrite.

## Served message gate

Select from the released request: `write-message` / `edit-message` use the
message-draft branch of `prose.md`; `analyze-message` uses its message-analysis
branch. Read the actual artifact and necessary source/context, not only the
receipt. A permitted short analysis can be read in full in the reply, but
draft units still require their complete text file.

Check recipient, expressed stance, known state, placeholders and the scope
of any edit. An apology/agreement/promise cannot be added merely to sound
warmer. Unknown results cannot become confirmed failure, and a retry control
does not establish safety. Sending and rendered/implemented interface behavior
need separate authority and evidence, not a Writer self-review claim.

Use checked / unmet / unverified criterion evidence, never legacy lint or
four-pass counts. Humanizer is explicit-request only and never a QA rewrite.
Unmet criteria go back to Writer; unavailable required evidence stays NOT
verified. Reports use only necessary quotations and do not expose secrets.
Analysis is a report, not a new message needing a greeting, apology or action.

## Served copy gate

Select from the released request: `write-copy` / `edit-copy` use the copy-draft
branch of `prose.md`; `analyze-copy` uses its copy-analysis branch. Read the
actual output and supplied sources; for edits also read the original and named
changes, and for comparisons read both inputs. A permitted short report is read
in full in the reply; actual draft units still need a complete durable file.

Check the approved message, offer and qualifications across headline, body and
action. No invented proof, urgency or altered conditions; a style preference
does not authorize a stronger claim. An action is required only when the purpose
calls for one. Body fields must be separable from production and QA notes.

Use checked / unmet / unverified evidence, not legacy lint or four-pass counts.
Humanizer is explicit-request only and never permission to repair during QA.
Unmet criteria return to the same Writer session; unavailable required evidence
is NOT verified. Analysis is a report, not a new sales page requiring a CTA,
offer or proof slot. Writing acceptance does not certify conversion performance,
legal clearance, a working flow, email delivery or publication approval.

## Served script gate

Select from the released operation, not solely the Writer's receipt:
`write-script` / `edit-script` use the draft branch in `script.md`;
`analyze-script` uses its analysis-report branch. A permitted short analysis
is read in full in the reply; actual script drafts still require complete files.
Never require the analysis report to contain a new script, raw speech input or
production fields merely because its target is a script.

Inspect the actual master, required exports/production notes, brief and evidence.
For edits read the original and authorized unit/field changes; for comparisons
read both targets. Check stable IDs and speaker attribution, exact verbatim
boundaries and consistency across required exports. A plain narration file has
no scene-table requirement. Raw speech input is words only, not structural labels
or `.production.md`. Retired IDs are not recycled or spoken.

Use checked / unmet / unverified evidence, not legacy lint or four-pass counts.
Humanizer is explicit-request only. Missing required evidence remains NOT verified;
text acceptance does not establish actual duration, rendering, pronunciation or
synchronization. Changed scripts need renewed approval and downstream evidence
may need rechecking. Defects return to Writer, not a local rewrite or media call.

## Outline gate — outline units

The cheap moment to catch the expensive defect:

- The structure serves the plan leaf's decisions: the claim is the
  spine (article), reader tasks map to sections (docs), units/beats
  cover the story with stable IDs and explicit order (script), the set's
  decomposition matches the plan.
- The tone samples land the decided register — pick one WITH the
  user when taste is theirs to judge; the choice binds the piece
  units that follow.
- Approving the outline fixes structure and tone: later piece
  feedback that reopens them is a plan change, not a revision.

## Full gate — piece units and whole jobs

1. **Evidence check** — the complete file at its durable path and the selected
   operation's applicable criterion evidence, sources and assumptions. Do not
   require fixed pass names or a statistical score. A missing required check
   means NOT verified. Permitted short analysis replies use their report gate.
2. **Read it** — the whole file, against the brief: type, audience
   fit, register stability, length, required facts present.
3. **Source trace (spot-check)** — load-bearing claims, quotes,
   numbers, and URLs resolve to the pasted sources; a claim that names a
   dedicated fact ledger or evidence record resolves to that record,
   wherever the requester's own workflow keeps it. An unsupported
   claim fails the unit regardless of polish.
4. **Contract check** — select the operation-specific branch in the family
   contract below. Script drafts honor the actual producer fields, stable IDs,
   isolated verbatim text and applicable verified bounds. Script analysis uses
   the report branch, not those draft requirements. Intended timing is not
   measured playback.
5. **Verdict** — pass → accept; the text becomes the requester's accepted
   deliverable to consume, integrate or forward. Fail → itemized,
   quote-anchored feedback to the same session, same unit.

## Evidence-anchored scoring

Apply this rubric within the existing gate for all six served families:
Post, Article, Document, Message, Copy and Script, across write/edit/analyze.
It includes released outlines and analysis reports, not planning consultation.
Select the family, format and operation from the released request, not the
output name. The score summarizes the operation-specific checks; it does not
add a second production review or replace the common evidence floor.

The requester scores its own reading of the actual candidate, brief and
sources; Writer's self-review remains checked / unmet / unverified, not
self-scoring. This is an ordinal editorial judgment, not a statistical
naturalness measure, authorship detector, lint score or claim of objective
measurement. Use the selected branch in [prose.md](prose.md) or
[script.md](script.md) for concrete acceptance anchors; do not assume
Writer's profile-local references are loaded.

Before scoring, identify the released operation, unit, format, scope and
mandatory criteria. Apply each axis only to that scope. Record an excluded
axis as not applicable with a reason; exclusion is not a pass or a substitute
for missing evidence. Required evidence that cannot be inspected remains
unverified with no numeric score and blocks acceptance of that requirement.
Unrelated factual questions or downstream work outside a bounded text edit
remain disclosed separately, not newly imposed acceptance criteria.
For a piece under an approved outline, assess whether it follows that outline;
do not re-score the settled structure or tone as a new taste decision.

| Axis | Inspect |
| --- | --- |
| Purpose | The requested answer, action or editorial operation is fulfilled. |
| Structure and usability | The reader can find and use the relevant information in this format. |
| Reasoning and evidence | Claims, comparisons, sources and qualifications support one another. |
| Information economy | Necessary context survives; repetition and generic filler do not bury it. |
| Expression fit | Wording, register and medium suit the supplied audience and conventions. |
| Fidelity and voice | Meaning, certainty, attribution and supplied voice survive without fabrication. |

| Score | Observable anchor |
| --- | --- |
| 4 | No material defect found within the inspected scope; the purpose is fully served. |
| 3 | Usable as delivered; only optional, local improvements remain. |
| 2 | A specific defect affects the purpose and needs correction. |
| 1 | A major gap or structural failure needs substantial correction within the agreed scope. |
| 0 | The assessed requirement is absent or contradicted. |

Accept only when every applicable axis is at least 3, every mandatory criterion
is checked and no critical defect remains. Do not average away a failing axis
or ask for a rewrite just to turn 3 into 4. Fabrication, material meaning reversal
and omitted mandatory conditions fail regardless of other scores. Authorized
fiction is not fabricated evidence. A valid unchanged edit can earn 4.

For each axis record score (or unverified/not applicable), quoted passage or
section/unit reference, and reason. An omission cites the missing requirement
and the inspected location where it was needed. For a score below 3, also state
the reader impact and required outcome; "make it more natural" is not actionable
evidence. For analysis, assess the report's answer, source-anchored observations,
reasoning and separation of fact/interpretation/unknowns, not the source's quality
or the presence of a newly drafted artifact. Never demand invented findings.

Keep the scorecard in your own QA/session record with the candidate path,
released unit and review round (or the exact permitted short report reply).
Do not inject it into recipient-facing text or invent a new delivery file.
Summarize acceptance and material caveats to the requester; show the full
scorecard when requested. Return actual defects to the same Writer session
under the correction ceiling below.
Passing this acceptance is neither user approval nor publication authorization.

### Correction ceiling

Allow at most two corrective returns per released unit after the initial QA
and before acceptance. This overrides a general "iterate until acceptable"
instinct for writing; it is a ceiling, never two mandatory passes. Re-read
the latest candidate and required exports each round, check the cited changes
and surrounding continuity, and record the result against that candidate.
A reused path or old score cannot establish acceptance of changed contents.

After the second returned candidate, accept if it passes; otherwise stop and
return unresolved findings to the requester. Stop earlier for missing material,
conflicting requirements, broader authority or a changed editorial direction.
Diagnose recurring defects rather than asking for synonyms or silently adding
rounds. Renaming a file/finding or resuming a session does not reset the budget;
an extension requires an explicitly revised release. Escalation is not acceptance.

A new consumer/producer defect after acceptance suspends that acceptance and
returns to the same Writer session under an explicit corrective release with
its own scope and ceiling. Do not suppress it because pre-acceptance rounds were
spent, or reset an unresolved old finding by calling it a consumer defect.
Changed protected decisions still need the relevant approval; a consumer's
finding itself grants no broader authority or publication permission.

Source: adapted from [natural-japanese v1.5.0 evaluation rubric](https://github.com/coji/natural-japanese/blob/v1.5.0/skills/natural-japanese/references/eval-rubric.md).
The 0-4 anchors, acceptance floor, correction ceiling and role split are local policy;
upstream's 90/92 thresholds and mandatory personal warmth are not adopted.

## Handoff note

A part fails its CONSUMER's needs (a script the producer cannot
render, copy whose claim the marketer's inspection strikes) → the
defect returns to the writer session as a normal feedback turn; the
consumer never edits the part.

## Who reads this

Any requester that calls Writer directly — assistant, engineer, creator or
marketer — owns its own acceptance of the returned candidate using this
contract. It needs no other file from this or any other profile: the brief,
fact ledger or evidence record and revision budget it applies above are the
caller's own, tracked in whatever form its own workflow already uses. Writer
does not run this contract as self-QA; its own self-review stays
checked / unmet / unverified, per [writer-pipeline](../../SKILL.md).
